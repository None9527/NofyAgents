# 入口与作用域:全局核心 + workspace 感知 —— 代码结论与用户侧问题

> 2026-08-22 · 分支:二次开发分支 · 触发:用户提问「两类 harness(coding 类以 workspace 出发 / 助手类以 home 出发)区分两个入口是否增加用户负担;能否全局为核心 + workspace 优先感知」,继而追问「是否需要一个全局入口(如 home),下面是用户自行选择的 workspace;Codex 以项目对话分类、无全局入口,对计算机直接对话的体验不行」。

## 1. 基于当前代码的结论(第一部分)

### 1.1 入口在实现层从未分叉

- 单一二进制、单一状态根:`$NOFY_HOME`(`~/.nofy`)下一个 daemon、一个 control.sock、一个会话库、一个 memory 根、一个 trash、一个 lease 表、一个 schedule。不存在「项目态」与「全局态」两套存储。
- 基准的「项目入口 / 全局入口 / 执行入口」(benchmark-design.md §2)是**同一二进制的三种测试姿态**,是 harness 的切法,不是产品分叉。
- PRD 方向已钉死(os-agentic-prd-final.md 第 19 行):「Nofy 从『终端编程代理』演进为『运行在操作系统里的助手』……编程能力是它最强的专家,而不是它的全部。」即全局核心论。

### 1.2 作用域由 cwd 推导,不由用户选择(已是「全局核心 + workspace 感知」的雏形)

- 会话:`$NOFY_HOME/sessions/<cwd 路径编码>/`,按启动目录分区、同库可跨项目检索(`sessions list/search --all`,W-8)。
- 记忆(nofy-memory/src/storage.rs):全局根 `~/.nofy/memory/` + 工作区子目录由 **git 仓库身份**(`org/repo`)推导;全局与工作区记忆共存、读取合并;临时目录识别为 ephemeral 不产生持久工作区状态。这是该模式的标准样板。

### 1.3 真实的「分裂感」来源(该修的不是入口)

1. 动词作用域默认值不一致、不可见:`memory clear` 默认工作区;`trash`/`lease`/`schedule`/`approval`/`task`/`forensics` 默认全局。
2. 两种执行姿态:交互会话进程内跑 agent;委托/调度/审批走常驻 daemon。用户不关心但分裂存在。
3. 审批/许可两套机制:进程内工具许可走 ACP(headless 非 yolo 即 fail-closed);daemon `ApprovalBroker` 是另一套,`nofy-shell` 无向其发 `ApprovalRequest` 的通路。

## 2. 用户侧问题(第二部分):要不要一个全局入口(home),下挂用户自选 workspace

### 2.1 对照产品入口模型

| 产品 | 顶层组织 | 有无「home/这台电脑」行 | 对计算机直接对话 |
|---|---|---|---|
| Codex(截图 2026-08-22)| 项目列表(新对话/PR/站点/已安排/插件 + 项目)| **无** | 不行:必须先选项目 |
| pi(coding-agent)| 项目(cwd)为信任/会话边界(`sessions/--<cwd>--/`)| 无 | 不行 |
| OpenClaw | 常驻 Gateway = 个人助理中枢,渠道为表面 | **有**(gateway 即机器级身份)| 行 |
| hermes | `$HERMES_HOME/state.db` 单状态根,多平台消息 | **有** | 行 |
| Nofy(现状)| 状态全局、作用域 cwd 推导,但**交互面没有显式 home 会话目标** | 隐式(在 ~ 启动 = 又一个 workspace slug)| 勉强:能用但 home 无特权身份、无可见指示 |

### 2.2 判断

- **需要 home 作为默认顶层身份**,但不是「第二个入口」:把全局层设为助手默认身份,workspace 是其下可挂载/可收窄的焦点。用户不选入口,选焦点。
- 理由(用户测):「对计算机说话」的任务(整理下载、找发票、磁盘占用、提醒、跨项目总结)**没有自然项目**;项目优先的顶层组织强迫用户做不自然的选择,Codex 截图即此形态。
- 实现原则:保留 cwd 自动感知(进 workspace 自动收窄、workspace 优先),手动选择仅作**显式覆盖**(全局会话里挂载某 workspace);作用域必须**可见**(当前是 global 还是某项目)且**可切换**。
- 交互面缺口(现状到目标的最小距离):① 显式 home 会话目标(TUI 侧栏首行「home/这台电脑」,截图形态的倒置);② 作用域指示器;③ 全局会话挂载/卸载 workspace 的动词;④ 动词默认作用域对齐表。

### 2.3 待验证(用户旅程探针)

设计一组「无自然项目」任务(整理下载类、全盘找文件、磁盘归因、定时提醒、跨项目问答),在当前 CLI 上跑,记录体验断点(作用域不可见、home 无特权、动词默认作用域踩坑),作为 §2.2 缺口的实证排序依据。
