## Scope & method

This manifest covers every renderer chunk whose content is **pure syntax/theme data**:
TextMate grammars (shiki languages) and VS Code color themes (shiki themes). These chunks are
frozen `JSON.parse(...)` payloads with no application logic and receive **no semantic renaming** in D8.

Identification method:

1. Every `JSON.parse(...)` payload was extracted from each of the 757 `.js` chunks (backtick, single- and double-quoted literal forms) and parsed.
2. Classification by self-describing fields: `scopeName` + `patterns` ⇒ TextMate grammar; `colors` + `tokenColors` + `type` ⇒ VS Code theme.
3. Each payload was deep-compared (canonical-JSON equality) against upstream data:
   `@shikijs/langs@3.23.0`, `@shikijs/langs@4.0.2`, `@shikijs/themes@3.23.0`, `@shikijs/themes@4.0.2`, `@pierre/theme@0.0.28`.
4. Hash twins were paired by **payload identity** (SHA-256 over canonical payloads), not file bytes —
   two twin files can differ only in their `import` specifiers while carrying identical data.

## Key findings

1. **Two shiki data snapshots coexist in the bundle.** The app ships shiki 3.23.0 (meta package pins
   `@shikijs/*@3.23.0`), but for 13 language/theme names a second copy matching `@shikijs/*@4.0.2` data
   is also present (the restored `node_modules` likewise contains both). Drift names: bird2, cobol, css, dart, emacs-lisp, go, horizon-bright, kusto, nextflow-groovy, php, ruby, ts-tags, typespec.
   For each of these, one hash twin is byte-exact vs 3.23.0 and the other byte-exact vs 4.0.2.
2. **`horizon-bright` type bug as version marker**: the 3.23.0 copy carries `"type":"dark"` (a tm-themes
   bug); the 4.0.2 copy has the corrected `"type":"light"`. Useful fingerprint if the copies are ever renamed.
3. **`go` name collision**: the two `go` snapshots were emitted as `go-z0eca2a7.js` (3.23.0) and
   `go-2-30ynai.js` (4.0.2 — Rollup appended `-2` to resolve the basename clash).
4. **Pierre themes are not shiki themes.** `pierre-dark-*.js` / `pierre-light-*.js` match
   `@pierre/theme@0.0.28` (github.com/pierrecomputer/theme) exactly; they are pulled in by the xlsx
   preview (`previewPaneOfficeXlsxContent` chunk via `@extend-ai/react-xlsx@0.16.0`). Single copy each.
5. **No Monaco.** No monaco-editor grammar/theme chunks exist in `out/renderer/assets/`; all
   syntax/theme data is shiki/TextMate-format.
6. **Tier corrections** (`/tmp/chunk-tiers.json` `grammar_data`): `c4Diagram-*`, `journeyDiagram-*`,
   `sequenceDiagram-*`, `chunk-U2HBQHQK-*` are mermaid v11 runtime chunks, and `arc-*` is d3-shape —
   none are grammar/theme data (see Excluded below). Conversely 34 true data chunks sit in the
   `grammar_data` tier and 568 in `vendor`; all 602 are covered here.
7. Multi-payload grammar chunks (inlined sub-grammars): `angular-html` (5), `vue` (5), `ts-tags` (6),
   `angular-ts` (3), `cpp` (2: cpp-macro), `jinja` (2: jinja-html). Most other composed grammars
   (php, blade, liquid, …) import their embedded languages as separate chunks instead.
