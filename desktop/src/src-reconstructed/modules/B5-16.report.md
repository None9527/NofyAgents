### 4.4 局部弧助手 ≡ arcSegment 等价性证据（脚本 Part D，6 项全过）

jsx 条目内局部助手（actionButtonHelp 的 `C`、leftRightRibbon 的 `k`、can 的 `c`）与
`arcSegment`（pptxEngineGeometry.ts 61–75）逐项一致：端点公式
`c = e - n*cos(o), l = t - r*sin(o), u = c + n*cos(s), d = l + r*sin(s)`（≡
`endX = cx + rx·cos(start+sweep)`）与 svg 模板
`` `A${n},${r} 0 ${+(Math.abs(a) > 180)},${+(a > 0)} ${u},${d}` ``（≡ arcSegment 的
`+(Math.abs(sweepDeg) > 180)},${+(sweepDeg > 0)}`）。`H`（ribbon/scroll 族用）svg 标志为
`+(a >= 0)`，与 arcSegment 的 `+(sweepDeg > 0)` 仅在 sweep=0 退化弧上有别——本批全部调用
sweep ∈ {±90, ±180, ±270}，无行为差（§5-4）。

## 5. 勘误（只记录，不改动既有文件）

1. **curvedleftarrow 区域顺序偏差**（pptxEngineGeometry.ts 1664–1672）：`buildMultiRegionPaths`
   对 curvedrightarrow/curvedleftarrow 一律返回 `[remainder, outer]`；源 Ti（jsx 8103–8117）仅
   `curvedRightArrow` 为 `[remainder, outer]`，`curvedLeftArrow` 为 `[outer, remainder]`。
   影响：`bo`（jsx 11850）取 `o[0].d` 为主轮廓，既有实现下 curvedleftarrow 的主轮廓取错段。
   本批 `wrapSplitPresetRegions` 为忠实版；整合期修复见 §6-4。
2. **多区域查表仅小写**（pptxEngineGeometry.ts 1689）：`MULTI_REGION_SHAPES.get(normalized)`
   只查小写键，而 ji 键含 camelCase（actionButton*/leftRightRibbon/ellipseRibbon*/smileyFace/
   can/bevel/cube/foldedCorner/flowChartOfflineStorage），这些预设经 `buildMultiRegionPaths`
   永远落到单路径分支。源 Pi（jsx 10857–10861）为「小写优先→原名回退」；本批
   `resolveMultiRegionPreset` 为忠实版。
3. **DEFERRED_MULTI_REGION_ANCHORS 锚点漂移**：38 项中 22 项行号与 jsx 实测不符（§2.1 列出实测行），
   其中 ribbon/ribbon2/horizontalscroll/verticalscroll 四项严重漂移（指向 callout 条目体内）。
   整合期删表时一并作废即可（§6-1）。另：任务口径称「36 预设」，登记表实测 38 项。
4. **arcSegment sweep 标志边情**（pptxEngineGeometry.ts 72）：`+(sweepDeg > 0)` vs 源 H 的
   `+(a >= 0)`；sweep=0 为退化弧，本批与既有调用均未出现，无实际行为差。
5. **pptxEngineGeometry.ts 头注释空诺两处**：17 行称 Ai「本文件末尾登记」，实测文件末尾（1745 行止）
   无 Ai/ki 登记（本批已补）；14–21 行区段表称 ji 为「9609–10500、actionButton 等 24 个」，实测 ji
