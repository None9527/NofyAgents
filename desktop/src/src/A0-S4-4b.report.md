## 7. 教训（供 S4-4c）

1. **tsc 二进制必须用 `desktop/src/src/node_modules/.bin/tsc`（5.9.3）**。`web/node_modules` 的 5.6.3 会对 `Uint8Array<ArrayBuffer>`
   报虚假 TS2315，且其 esbuild 版本面亦不同；本批曾因此误报一次。
2. **harness 的 added/removed 计数 ≠ 判定**：`s44b-unit.sh` 打印的是 strip 后、再 comm 前的规模；
   必须 `comm -23/-13 <(u4-strip 双侧)` 之后才是真残差（u3 曾以 559/541 起步，真残差仅 96/6）。
3. **组件文件的手写导入行是最高风险面**：迁出体逐字可验，但导入行由人重写——本批 `Sparkles as SparkleIcon` 之误
   （Sparkle ≠ Sparkles，两个不同图标）全靠 emit-diff 的图标模块整体消失才暴露。规则：lucide 一律照抄原文件别名形态
   （`X as CloseIcon`/`Trash2 as TrashIcon`/直名 `SparkleIcon`），禁止「基名 + as 语义名」臆造；迁后必过 emit-diff。
4. **ambient declare 复制是 emit 中立的**，但**运行时值（testid 常量/助手函数）绝不可复制**——唯一消费随迁，
   多消费留守补 export + import 回取；回取边只要目标是函数声明（提升）或渲染期访问的 memo 常量，即环安全（承 4a U6–U8 实证，本批 11 条回取边全部一次通过）。
5. **模块私有族迁出后若无任何 re-export/import 边，则保持「悬置」**：pptx chip 六实体原即死码（pre 捆绑 0 次出现），
   迁出后不接线 = emit 逐字不变；反之若补 import 反而会引入副作用求值、改变 emit。
6. **esbuild 会按实际使用剥除导入规格符**（shim 的 TooltipContent 迁出后不再被引用 → 发射行自动消失）：
   源面保留原导入行是安全且字节忠实的，不必为「未用导入」做修剪；外部（wildcard external）模块的 import 行
   会按模块逐条发射，1 进口变 N 进口属预期重排，按「同模块同导出」核数即可。
7. **注释块内的 `*/` 序列会提前闭合块注释**（`MODEL_SELECT_*/MODE_…` 之误致 TS1109 风暴）：注解块写完后先 `grep -n '\*/'` 逐行核对。
8. **跨段符号普查要全表扫描**：u4 首轮以精选表扫描，漏掉 `shouldHydrateFullHistory/hydrateRetryDelayMs/findActiveQueryRow`
   三个 §6→§5/§8 消费边（tsc 兜底捕获）。S4-4c 应直接以「段内全部顶层符号 × 保留区 grep -nw」全表扫，不靠手工选表。
