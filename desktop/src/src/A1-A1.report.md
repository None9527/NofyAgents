### 1.3 对 host 暴露的 IPC 面（阶段 B 消费）

utilityProcess postMessage，附加式监听（不触碰既有 host 消息分派；`KERNEL_HOST_MSG` 常量在
`kernel-bridge.js`）：

- **host→main** `{ type:"nofy-kernel-call", requestId, op, ... }`
  | op | 参数 | 语义 |
  |---|---|---|
  | `rpc` | `{method, params}` | 标准 ACP request（session/new、load、prompt、list…） |
  | `ext` | `{method, params}` | 内核扩展 request，幂等补 `_nofy/` 前缀（§2.2） |
  | `notify` | `{method, params}` | notification（session/cancel 必须走此形，§2.1） |
  | `cancel` | `{sessionId, meta?}` | 停止：cancel 通知 + 该会话挂起权限请求自动回 cancelled（§2.3） |
  | `respond` | `{id, result}` | 应答 server→client 请求（权限/问答/计划模式/表单） |
  | `ready` | `{}` | → `{ready, url, endpointMode}` |
  | `state` | `{}` | → `stateSnapshot()`（initialize 结果、modelState、capabilities） |
- **main→host** `{ type:"nofy-kernel-result", requestId, ok, result? | error? }`
- **main→host** `{ type:"nofy-kernel-event", event, payload }`
  - `event:"acp"` → `{kind:"notification"|"request", method, params, id?}`：全部入站帧按
    method 多路复用（`session/update`、`_nofy/session_notification`（含 `turn_completed`）、
    `_nofy/sessions/changed`、`_nofy/models/update`、`session/request_permission`（带 id，
    经 `respond` 应答）…）
  - `event:"status"` → `{connected}`；`event:"ready"` → `{}`

单例本体事件面（main 内直接消费）：`status / ready / acp / update / ext-update /
notification / sessions / models / settings / queue / replayed / permission /
ask-user-question / exit-plan-mode / elicitation`。

## 2. 相对 acp-client.js 的修正（含 PORTING-PLAN §2 证据）

1. **`session/cancel` 改为 notification**（§2.1 表、§2.5.1：`acp-client.js:196` 当 request 发，
   内核回 -32601 且 `catch {}` 吞掉）。`cancel()` 现以无 id 帧发送，并按 §2.3 同时把该会话
   所有挂起 `session/request_permission` 应答 `{outcome:{outcome:"cancelled"}}`。
   实测：request 形 → `-32601 Method not found`（负对照复现）；notification 形 →
   prompt 7–10ms 内以 `stopReason:"cancelled"` 收尾（§2.1 实测 12ms 量级一致）。
2. **`initialize` 携带 `_meta.clientIdentifier="nofy-desktop"`**（§2.1 initialize 请求侧要点：
   内核认识该标识，Desktop 类权限选项集更丰富）。旧 handshake 未发 `_meta`。
3. **`_nofy/*` 前缀纪律（双向）**（§2.2：线上全部下划线前缀）。新增 `ext()` 幂等补前缀
   （`a/b` | `nofy/a/b` | `_nofy/a/b` → `_nofy/a/b`）；入站扩展通知按 `_nofy/` 名分派。
   实测负对照：不带下划线的 `nofy/session_summaries/workspace_list` → `-32601`。
4. **initialize 结果按活体形状落库**：`agentVersion` 在 `_meta.agentVersion`（顶层无此键）；
   `modelState = _meta.modelState = {currentModelId, availableModels[]}`（§2.4 模型表唯一来源，
   `stateSnapshot()` 直接供阶段 C 模型门槛合成快照使用，§2.7）。
5. **挂起防护**：`rpc(method, params, timeoutMs)` 可选超时（§6 风险 4：`session/set_mode`
   对非活跃会话挂起，host 调用需超时）；server→client 交互请求（权限/问答/计划模式/表单）
   无监听者时按 §2.3 形状自动回 cancelled，避免内核悬挂（旧代码对未知请求回 `{}` 的兜底
   保留于 default 分支）。
6. **错误传播**：rpc reject 携带 `err.code`（如 -32601），应答分派加 `method===undefined`
   守卫，杜绝 server→client request 误入应答分支。

**吸收保留的已验证部分**：帧分派骨架、pending 表、断线重连（2s）、ready-waiter、
`clientCapabilities.fs={false,false}`（§2.3 桌面建议，内核用本地实现）、事件名
（status/update/notification/sessions/replayed/permission）、`respondPermission(id, outcome)` 形状。

## 3. workspace-registry 收编（A2）

- **违例消除**：原 `client()` 懒建第二条 ACP 连接（`new NofyAcpClient({clientName:
  "nofy-desktop-ws-enum"})`，对同一内核端点）——§2.3 单客户端中继约束的现存违例
  （第二条连接会抢走事件流）。现全部枚举经单例 `client.ext("nofy/session_summaries/workspace_list")`，
  全进程对内核只剩一条 WS（§4 实测）。
- **枚举逻辑原样保留**（`workspace-enum.js` 纯函数）：
  - 主路 `_nofy/session_summaries/workspace_list` → `{all_sessions:{<cwd>:[Summary…]}}`，
    5s 超时（`ACP_TIMEOUT_MS`）；
  - 回退 `~/.nofy/sessions/` 目录扫描（URL-decode 目录名＝cwd），按 mtime 新→旧、
    上限 200 行（`DIR_SCAN_MAX_ROWS`，FIX-WS 防 /tmp 残留灌满侧栏）；
  - 标题回退链：`generated_title || session_summary || firstUserQueryTitle(chat_history.jsonl
    <user_query>) || sessionId 前 8 位`（`session-title.js` 共享件未动）；
  - 缓存：ACP 成功 20s TTL；dir-scan 负缓存 3s（尽快回主路）；
  - `listWorkspaceSessions` 懒加载（scan 形态强制刷新一次 ACP 再取）。
- **renderer 契约不变**：`zcode:nofy-list-workspaces` / `zcode:nofy-workspace-sessions`
  通道名与 `{ok, source, at, workspaces}` / `{ok, workspacePath, sessions, source}` 形状逐字保留。
- 注册即预连改为 `ensureNofyKernelClient()`（单例握手一次，兼作启动引导；失败不钉死，下次调用重试）。

## 5. 阶段 B 消费清单

1. **会话主流程**：host 经 `nofy-kernel-call`（`rpc`/`notify`/`cancel`/`respond`）驱动
   `session/list|new|load|prompt`、`session/cancel`（notification）、权限应答
   （`respond` + `_nofy/sessions/changed`/`session/request_permission` 事件经
   `nofy-kernel-event{event:"acp"}` 取回，带 id 可直接回）。
2. **模型**：`state` op → `stateSnapshot().modelState`（`initialize._meta.modelState`）；
   运行期变更经 `_nofy/models/update`（'models' 事件已分派）；`session/set_model` 走 `rpc`
   （建议带 timeoutMs，§6 风险 4 同类）。
3. **任务列表同步器**：数据源 `_nofy/sessions/changed`（'sessions' 事件）+
   `ext("nofy/session_summaries/workspace_list")`（枚举件已就绪）。
4. **侧栏枚举**：`workspace-enum.js`（renderer IPC 已在单例上运行，形状不变）。
5. **回归基线**：`scripts/acp-probe5.mjs`（17 断言；会话流程改动后复跑，
   尤其 cancel/权限/WS 计数三项）。
6. 注意：host 侧 parentPort 监听需在阶段 B 新增（本阶段只落 main 侧）；
   `ZCodeProtocolClient` 与 adapter 按 §阶段 D 时序最后拆。
