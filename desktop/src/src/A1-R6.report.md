## §4 裁决记录

### 4.1 cancelPendingRemoteConnection 第二消费面（209263–209809）→ 不改指

编排器持 `options.cancelPendingRemoteConnection`（K3t，options 面）并在
Y3t 接线处（对应 bundle 209805–209810 platform-method wiring）由 platform
服务方法直供。R5 落地之 `RemoteConnectionDeep.useCancelPendingRemoteConnection`
（uEt）为 RemoteWizard fOt 专用钩子，二者同名异源（一为服务方法、一为钩子封装）。
强行改指将改变调用形态（钩子 vs 方法），违背逐字原则。裁决已志于
OnboardingLoginLeaves 头注与 SplitLayoutDeep 尾表。

### 4.2 Hn 跨 chunk 溯源

真形在 src chunk 而非 styles：`function t(e)`（src-HCld2afU.js 2–13）→
src 导出块 `t as Ns`（9766）→ styles 导入块 `Ns as Hn`（535）。两跳再导出，
转录归宿按域邻接（z2 之逆）置 SplitLayoutDeep §F-R6，头注/尾表志之。

### 4.3 H2/U2 收敛方向

证据见 §1.3：live 实例独占全部终端消费面 + bundle 呈现层直消费；休眠实例
零终端消费者。方向 = ConfirmDialog.tsx canonical、stores 侧 shim（与任务建议同）。
跨实例请求不可见之潜在风险（两 zustand 实例各持 pendingRequest，经 stores-core
路径发起的请求对对话框呈现层不可见）随旧实例删除而消除。
导出面维系：`useConfirmDialogStore`/`useConfirmDialog` +
`ConfirmRequest`/`ConfirmRequestInput`/`ConfirmDialogState` 三型
（stores-core.tsx 70–71 行 import 面逐一不破，esbuild 实测通过）。
tombstone/头注：shim 文件头注全文志之；ConfirmDialog.tsx H2 注释增
A1-R6 双实例收敛注 + canonical 导出面行注（`export { ConfirmDialogStore as
useConfirmDialogStore }`，75–76 行）；`ConfirmDialogStoreState` 转导出。
