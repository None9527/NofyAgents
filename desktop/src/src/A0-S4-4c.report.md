## 7. 教训（供 S4-5）

1. **esbuild 门必须带 5 个通配 external**：U34 实测，缺 `*pdf-viewer/*pptx-preview/*duke_sheets_wasm` 时，
   经 LazyPreviewViewers 传递的 vendored 动态 import 报 3 个假性 Could-not-resolve。通配形态与文件迁深无关，是 SHIM MODE 深迁后仍可逐文件过门的前提。
2. **内联型动态导入**（`import("./X").T`）不在 import 语句行上：迁前必须 `grep 'import("\./' 与 'import(\`\./'`；
   本批 3 处（MarkdownRenderer ×2、XlsxPreviewWasmBridge ×1 duke）均以迁移器 extra（`import\("\./=>import("../../modules/`）处置。
3. **迁移器幂等护栏**：backup 已存在时二次调用即中止 —— U34 发生过一次误触二次调用，状态无损（组件件/shim 均未被覆盖）。
4. **整文件迁移是末批主旋律**：53/53 目标均为 100% 组件性质，单元级拆分在 4c 零使用；普查后直接整件迁移 + 全量审计是最高效路径。
5. **通配 external 转位会累积**：4c 后累计未配对集 = 8 对导入路径转位（5×UsageStatsUiParts + 3×MarkdownVendored）。
   S4-5 的累计 diff 必须把该白名单作为已知常量，不可当作新残差追查。
6. **无导出面文件**（ProcessMonitor）→ shim 用 `import '../components/…';` 副作用转发，注解注明"原文件无导出面"。
7. **declare 分配**（承 4a 矩阵）：ambient 符号（AppErrorBoundary、useControllableState）继续留守 shim 逐字副本；
   本批 2 例均一次通过。
8. **审计器边界**：`export default <expr>;` 的 `default` 不计入值名表；留守原件不可混入 shim 审计集 —— 两处误报模式已固化到 §5 记录。
9. **harness 计数陷阱复核有效**（承 4b）：unit.sh 打印的 added/removed 是 strip 前规模，判定一律以多集配对后的未配对 distinct 为准。
