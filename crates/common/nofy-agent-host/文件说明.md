## 启动

准备访问令牌引用文件，以及 `NOFY_KERNEL_ADMIN_TOKEN`、`NOFY_KERNEL_VIEW_TOKEN` 两个至少32字节、无空白的访问令牌。系统样例的模型凭据引用为 MODEL_TOKEN，默认从 NOFY_SECRET_MODEL_TOKEN 注入；样例模型地址和模型名必须改成当前环境可用的值。访问令牌与模型凭据是不同用途。

```sh
cargo run --locked -p nofy-agent-host -- \
  --state-dir /absolute/path/to/kernel-state \
  --access-file crates/common/nofy-agent-host/examples/access.json \
  --system-file crates/common/nofy-agent-host/examples/system.json \
  --listen 127.0.0.1:7331
```

`--system-file` 接受可编辑 SystemDocument 或锁定 SystemBundle；启动时校验、发布并按当前 generation 应用。当前已激活相同摘要时不增加记录。可以不传此参数，后续通过 API 导入文件。访问引用文件和 credential authority/prefix 是本机引导参数，不进入系统导出。更换机器使用相同的逻辑 authority，单独注入密钥；配置导入不会制造缺失的历史状态。

## API

所有 API 使用 `Authorization: Bearer <token>`，JSON请求体仍受32MiB传输接纳上限约束；它不是Agent交付包配额，纯打包、交付文件读取及来源式导出不设总字节配额。编译、输入、队列、缓存和执行各自的资源上限继续独立执行。身份检查在读取JSON前进行，未知/缺失身份返回401，缺少作用域返回403。read/edit/publish/resources/execute独立授予，包含资源定义的写入/发布/应用同时要求resources。当前授权覆盖该宿主的全部系统；未提供多租户隔离。

| GET `/api/v1/catalog` | read | 持久草稿、不可变发布、激活和应用回执 |
| POST `/api/v1/validate` | read | 单文件纯校验与冻结；不读取凭据、不执行业务 IO |
| POST `/api/v1/import` | publish | 校验并持久发布源文件或锁定文件 |
| PUT/DELETE `/api/v1/drafts/{name}` | edit | 带 revision 的草稿 CAS |
| POST `/api/v1/publish` | publish | `{draft,revision}` 发布指定草稿版本 |
| GET `/api/v1/releases/{release}` | read | 同一锁定单文件导出 |
| POST `/api/v1/plan` | read | `{system,release}` 对当前激活计算差异 |
| POST `/api/v1/apply` | publish | 原 ApplyCommand；回滚也应用历史 release |
| GET `/api/v1/systems/{name}/active`、`history` | read | 激活指针与应用历史 |
| POST `/api/v1/runs` | execute | 原子接纳 ManagedRunRequest，返回202；相同请求重放返回200 |
| GET `/api/v1/runs`、`runs/{id}` | read | 分页管理运行、原运行记录及子运行 |
| GET `/api/v1/runs/{id}/events`、`stream` | read | 持久事件页与 SSE；after/Last-Event-ID 续读 |
| GET/POST `/api/v1/runs/{id}/approvals` | read/execute | 查询运行树审批；精确原 ApprovalRequest 的不可变决定 |
| POST `/api/v1/runs/{id}/cancel` | execute | 取消未执行队列，或持久根取消并返回 cursor |
| POST `/api/v1/runs/{id}/inputs` | execute | 原 MailEnvelope；验证 root/child 收件地址和当前线程 |
| POST `/api/v1/actions` | execute | 持久接纳恢复/模型重试/子取消恢复命令 |
| GET `/api/v1/actions/{id}` | read | 命令完成结果或错误回执 |

运行请求为 `{run_id,thread_id,system,release,program,input}`，input 使用 `{text,attachments}`，仅 Agent 必填；release 是明确的已发布摘要。恢复命令为 `{command_id,run_id,command:{kind:"resume"}}`，另外支持 resume_after_cancel 的 through，以及 control 的原 RunControlCommand。嵌套控制命令的 command_id 必须相同。审批决定后再提交恢复命令，两步各自可幂等重放。

运行接纳与原队列在同一 SQLite 事务提交。客户端断开不会取消 worker；进程退出后从持久队列恢复。未知工具或模型副作用继续走原对账机制，不自动创建新的运行或重新执行。控制结果在同一根租约下确认，丢失租约时保留未确认命令。调度只读取轻量队首，分页跳过当前占用和退避任务；恢复编译放进 blocking pool。事件流关闭不影响任务；宿主关闭事件流并等待进行中的任务收束。

## HTTP工具和Hook（L2b2）

默认native工厂已经安装 resource.http/tool.http_connected/hook.executor。resource.http配置为 `{base_url,methods,credential_refs}`；tool.http_connected配置为 `{contract,path,method,input?,credential_ref?}`，通过标准connection依赖指向HTTP资源。Hook复用这一个工具Pack，经hook.executor与hook.subscription绑定事件。实际可校验示例为examples/http-system.json；服务端Hook接收完整HookEvent，并返回原HookDecision，如 `{decision:"patch",payload:完整新payload}`。

工厂只解析配置和URL，不创建客户端、读密钥或请求服务。调用时惰性初始化原HttpConnection，并复用原HttpToolFactory/dispatch 的映射、流取消、timeout和输出限制；相同编译资源中的工具共享客户端。凭据来源与模型是同一逻辑authority。添加无关HTTP连接不改变已有程序identity，修改路径/方法等配置需发布新版本；旧已发布程序保持旧配置，凭据值按后续实际调用更新。

HTTP基址无inline credentials/query/fragment，必须目录形式；输入不能覆盖URL/方法/密钥引用，路径不能跳出基址，禁止重定向与环境代理。资源写入/发布/应用需要resources作用域。当前这支持外部服务自定义方法；进程代码、全部原能力和执行中组合转换继续后续阶段。

## 每次运行的参数（L2d1）

GET `/api/v1/releases/{release}/programs` 以read作用域返回每个程序的kind、accepts_message、parameters_schema和default_parameters。Agent仍使用input消息；Tool使用parameters作为完整arguments，根workflow使用parameters作为入口输入，Event使用parameters作为payload。省略parameters保留发布默认值，显式null是独立的实际输入。静态schema与1MiB上限在接纳前校验；动态ToolSource的schema仍由原执行边界检查。

## 预算资源（L2e1）

默认常驻宿主在打开原runtime.sqlite后安装resource.budget与governance.budget_connected。前者config为空对象，绑定同一账本；后者以budget:Resource为标准依赖，配置limits/retry。限制字段和重试约束复用原预算引擎；配置/编译只绑定句柄，不产生enroll记录。可运行单文件见examples/budget-system.json。

资源身份来自可信逻辑authority、声明reference、ceiling、retry ceiling和持久化语义，不写本机数据库路径；同一配置锁已验证跨state-dir恢复。配置导出不携带历史账本。实际调用仍通过原storage_identity与根监督器校验，再使用原租约围栏做预留/结算；逻辑同名不能使用另一个物理DB的账本。旧InstalledBudget::install/GovernanceFactory身份保持兼容。

预算可作为required_governance约束整个系统。真实HTTP验证workflow额度用尽后阻止后续效果，resume保持已消费/预留额度。该配置发布仍遵守既有执行快照；运行中的预算变更属于后续组合转换。

## 根工具恢复（L2e2）

GET `/api/v1/runs/{id}/recovery/root` 需要read，返回根待处理调用或null（run_id、thread_id、checkpoint_revision、model_sequence、call），原子运行分页API保留。投影信息为候选，接受证据时在原根租约下重新校验冻结组合、运行归属和完整操作。

POST `/api/v1/actions` 的command.kind=reconcile_root_tool，receipt必须包含model_sequence、完整call、result、is_error；需要execute。使用全局command_id幂等接纳和原证据表，结果不可覆盖。Agent/Tool根恢复后沿原循环继续，无模型Tool仍不请求模型；启用预算时结算既有预留且不重置消耗。根workflow/Event及Tool包裹的可恢复控制器需定位实际原语子运行，不能替换控制器结果。

## 治理模型恢复（L2e3）

GET `/api/v1/runs/{root}/recovery/models?target_run_id=Agent运行ID` 需要read，缺省目标为根，返回原生待处理尝试。目标可为根Agent或记录的Agent后代；票据包含thread/run、operation/scope、请求指纹、generation及attempt，另返回原预留、unbounded_tokens和证据接纳状态。

POST `/api/v1/actions` 的command.kind=reconcile_model，receipt为ticket与result。result.kind=completed携带原ModelResponse；kind=failed携带原ModelFailure。execute作用域、原管理队列、根租约、检查点归属与不可覆盖journal共同限定接纳；之后由原采样边界使用证据，真实预算回执始终优先。费用按原上界保守结算，失败继续原显式/策略重试，重放不清空消耗。

此API管理已有治理模型派发意图；未治理旧入口尚未获得相同崩溃对账保证。不会因提交result而绕过权限、上下文变化或预算期限。

examples/model-recovery-system.json组合通用模型连接、外部协议制品、框架持久预算、提示词及源码工具。设置实际提供方目录URL/model、端点真正强制的endpoint_limits、Agent的settings.model.max_output_tokens与MODEL_TOKEN引用；令牌值由独立凭据后端注入。普通调用与对账使用相同导入/发布/执行接口，无需另编译Agent包。

## 无预算日志绑定（L2e4）

默认registry安装binding.model_journal，config为空对象，在program.definition.bindings或workflow host.bindings选择即可。examples/model-journal-system.json提供不声明预算的可装载系统，沿原凭据注入/发布/执行路径。恢复仍用/api/v1/runs/{root}/recovery/models和ReconcileModel，目标会标注unmetered=true，reserved无预留，不代表实际Token为零。无预算结果日志沿原SQLite/根租约保存，正常响应和显式重试保持原模型协议。


## 管理放弃验收入口（L2e5，阶段通过）

tests/http/abandonment.rs复用原模型HTTP硬退出子进程，覆盖根/子Agent、有/无预算四种场景：原POST actions鉴权、明确未知效果确认、线程封存、预算不变、原请求不重发与重开回执。生产API路由和展示层不改，abandonment通过已有动作查询返回；该套件已经编译；沙箱运行在端口绑定时PermissionDenied，放行审批又因登录令牌刷新失败未执行，不能视作已验收。凭据5项已通过。

权限更新后完整HTTP30项、凭据5项全部通过；新放弃测试四种真实硬退出场景已执行成功，历史权限故障不再阻塞。

## 持久安全停驻（L3a）

原 POST `/api/v1/actions` 的 execute 作用域接纳 `command:{kind:"park"}`；必须为已初始化、声明治理或 binding.model_journal 的根 Agent。GET `/api/v1/actions/{id}` 在安全边界前返回 finished=false，确认后使用原 Paused outcome，reason.kind=parked，含检查点 revision/digest。GET `/api/v1/runs/{id}` 的 parking 返回 requested/parked/released/rejected 和独立凭据。停驻请求和实际生效是不同状态；未知效果仍须原恢复/对账证据。

解除使用原 actions，command 为 `{kind:"unpark",park_command_id:"原Park命令ID"}`。可以撤销 pending 请求；已停驻时需原检查点精确匹配。解除不派发模型/工具，再提交 resume 或必要的 resume_after_cancel。pending 停驻让出原恢复命令；Abandon 继续优先。当前接口不支持 Tool/Event/workflow 根的内部停驻，也不构成 CompositionTransition。实际流程与进程故障验收见 tests/http/parking.rs 及[停驻契约](../../../docs/architecture/durable-agent-parking.md)。

## 安全边界的配置版本转换（L3b1）

POST `/api/v1/actions` 的 execute 作用域新增 `transition`：包含原 `park_command_id`、从 0 开始的 `expected_revision`、精确 `release` 和目标 `program`。宿主从同系统已发布版本恢复并冻结兼容目标；不接受上传的任意运行快照。转换成功仍为 Paused，不自动解除或执行业务；先 Unpark，再显式 Resume。原冻结提交和所有历史事实保留。

GET runs/{id} 的 `live` 提供当前有效版本摘要，GET runs/{id}/versions?after=0&limit=16 提供需 read 权限的有界历史摘要（单页 1..=32）。摘要不复制完整检查点对话，精确 release/program 可通过原发布导出接口检查目标配置。首批只支持模型连接、模型参数与静态 Prompt；其他有状态能力的变更拒绝。tests/http/parking/transitions.rs 使用真实 Sampler HTTP/SSE、工具和 Hook，验证同进程更新、接纳后硬退出重开、预算不变、旧效果不重放以及历史查询权限。详见[转换契约](../../../docs/architecture/live-agent-transitions.md)。

## 显式工具与订阅更新（L3b2）

同一 POST actions 的 execute 作用域新增 `command.kind=update_modules`，保留 park_command_id、expected_revision、release、program，增加 `update:{tool_catalog:bool,hook_subscriptions:bool}`；至少选择一项。仍从同系统精确已发布版本冻结目标，仍需显式 Unpark/Resume。配置编辑/发布的 Resources 与 Publish 权限保持原要求，不接受请求携带的任意快照。

有效版本使用 nofy.live/v2，摘要的 modules 返回累计工具迁移及 Hook epoch。静态工具和后续事件订阅从有效版本执行；人工响应模块路径也从有效冻结快照选择，不再误查旧提交。原策略、预算及受保护依赖不变，新工具不能绕过原准入。tests/http/parking/modules.rs 覆盖同进程热装载、转换应用后硬退出96/恢复、旧/新工具与Hook各执行一次，以及新加入 workflow Hook 的 Human 响应和回执重放。跨运行交接及完整有状态迁移仍按后续里程碑验收。

## 稳定会话入口（L3c1）

`src/api/sessions.rs` 提供 POST /api/v1/sessions（execute，{id,root_run_id}），GET sessions、sessions/{id}、sessions/{id}/turns（read）。显式接纳首个受管 Agent 任务后，后续同冻结配置任务继续使用原 runs/NextTurn 队列，预算沿用起点账本；不另建输入执行器或会话所有权缓存。列表按 id、轮次按原任务 sequence 分页，limit 1..=256。精确创建重试可读取不可变回执，不抢当前租约；不支持回溯合并已独立执行的多个根。

`tests/http/sessions.rs` 使用真实 Sampler HTTP/SSE 验证权限、连续对话、宿主重开及原额度；硬退出93场景在第二根模型请求派发后退出，以原模型对账接口结算首根账本中的预留，无重复请求。该阶段不是有效配置的跨根迁移，也不表示完整平台验收，见[会话契约](../../../docs/architecture/durable-agent-sessions.md)。

## 显式轮次与种子交接（L3c2）

POST sessions/{id}/turns（execute）接纳 SessionTurnCommand：command_id、source_run_id、expected_source_revision、expected_binding_revision（缺省0）与 turn。turn.kind=new 提供 run_id/input；kind=queued 提供 run_id/submission_digest。后者不改写原排队输入，只追加明确的 at-handoff 配置绑定；未固化种子时可 CAS 重绑，旧命令精确重试仍返回原接纳。GET sessions/{id}/turns/{run_id}（read）返回 admission 和 seed 摘要，原 runs 继续提供实际执行/事件/恢复接口。

`tests/http/parking/transitions/sessions.rs` 使用真实模型 HTTP/SSE、工具、Hook 和原后台 Worker：源根运行中更新后，将相同有效版本传入原排队任务与后继；硬退出94在新根请求派发后发生，重开时用原票据结算原会话预留、不重发模型、旧效果不重做，后续根仍受起点额度约束。原发布、资源权限和宿主强制约束不放宽，原入口未接纳任务仍保持配置混用保护。

## 外部制品与受限进程（L2f1）

POST `/api/v1/artifacts`（resources）接纳 `{schema_version:1,files:{相对路径:文本}}`，返回digest/files/bytes；GET artifacts（read，after/limit，1..256）分页，GET artifacts/{digest}读回包。1..128文件、1MiB/文件、2MiB源文本、4MiB编码；仓库最多1024包/512MiB，追加保留。resource.artifact 的规范配置为 `{bundle}`；输入文件/API可用 `{digest}`，Loader展开后才交给原编译器，导出锁包含完整源码。

POST `/api/v1/runtimes/probe`（resources，空对象）显式探测隔离，不执行模块。POST runtimes（resources）以 `{id,path,executable_digest,prefix_args,read_roots}` 安装当前架构Linux ELF64解释器；digest为实际文件SHA256，路径为本机绝对路径。GET runtimes（read）只返回可移植manifest，不返回路径。二进制被独立保留并在实际调用校验，最多256绑定/1GiB。prefix_args通常为解释器的隔离参数；read_roots只能收窄系统库目录，不允许授予内核状态、任意宿主目录或设备。

resource.process 配置为 `{runtime:{id,revision}}`；tool.process_artifact 以 environment/artifact 两项Resource依赖，配置 `{contract,entrypoint,args,input,scratch_files}`。入口必须属于包，scratch_files最多16个规范相对路径，缺省不可写；只允许读写预建文件槽，不可创建其他文件。仍用原JSON stdin/输出、权限、预算、取消、超时及恢复边界，可通过hook.executor装配Hook，不另建执行循环。

发行二进制在Tokio启动前识别私有helper入口，Landlock ABI3全量生效与seccomp为必需；不支持时拒绝，不降级。库依赖在manifest明确标为host-system-libraries-unlocked-v1，不表示OS/标准库完整锁定。嵌入宿主一次调用with_loader_helper选择兼容发行helper；普通脚本/工具/Hook版本修改不需要Rust注册或重编译。正常调用清理scratch；硬退出留下的目录不作为成功证据，原未知效果对账仍必需。详见[阶段契约](../../../docs/architecture/artifact-process-loader.md)，真实发行宿主、取消/超时、父进程死亡与迁移用例在tests/http/loader.rs及loader/process.rs。

## 锁定依赖与单份部署（L2f2）

旧resource.process保留其显式未锁定系统库语义；新增resource.process_locked，规范配置为 `{manifest}`，源配置可用 `{image:映像摘要}`。它仍作为tool.process_artifact的environment依赖；依赖文件、解释器、动态扩展、共享库、环境与参数共同进入映像身份。实际调用只允许读取映像/制品和声明scratch，无宿主系统库授权；动态解释器通过映像内glibc loader启动并禁用宿主ld cache。helper不继承声明环境，隔离后才注入目标程序，避免预加载绕过。

POST `/api/v1/runtime-images`（resources）接纳RuntimeImage；GET同路径（read，after/limit，默认8、1..16）仅返回digest/id/platform/files/decoded_bytes，GET runtime-images/{digest}读回完整映像。单映像4096文件、128MiB/文件、256MiB解压、24MiB编码；仓库64映像、编码/声明解压各1GiB，物化与暂存解压再限1GiB。所有ELF DT_NEEDED必须在声明库目录，gzip/base64/长度/摘要及缓存树严格校验；动态import/dlopen超出闭包时不回退宿主文件。追加历史及孤儿暂存仍占额度，不声称已有引用GC。

`nofy-runtime-image --definition /absolute/capture.json --output /absolute/runtime-image.json` 从显式本机定义捕获普通文件，输出已校验映像及stdout摘要，拒绝覆盖。files映射目标相对路径到来源绝对路径；trees映射目标目录到{path,exclude}，exclude为规范相对路径前缀；executable_files显式附加执行文件；入口/loader自动设执行位，不保留来源的特权位。env值用 `{kind:"literal",value}` 或 `{kind:"path",path}`，后者相对映像根，`.`代表根。打包器不自动执行ldd/来源程序推断依赖。Cargo默认运行仍是nofy-agent-host，不因新增CLI改变旧启动命令。

底层显式映像接纳仍可读取`{format:"nofy.deployment/v1",system:SystemFile,runtime_images:[RuntimeImage]}`，validate验证闭包但不上传/物化/运行，import须publish/resources权限，先接纳资源再发布，两者不是同一事务。该入口不是当前Agent打包器或系统导出的交付方式：编程打包器只接受依赖描述，GET releases/{release}/deployment只返回v2来源式声明，不再补齐依赖字节，缺少有效来源证明即失败。交付文件读取/来源式导出的32MiB包体检查已删除；显式映像接纳本身的24MiB编码、系统8MiB编译和16MiB运行版本等资源边界未改。运行快照只保存manifest，凭据与历史状态独立注入/迁移。

大载荷资源/配置管理最多并行2个，请求在鉴权后、解析JSON前等待许可；取消/审批/运行控制/事件不占用该许可，宿主关闭会唤醒等待者。实际进程准备另限2个，先异步取得许可再开始blocking文件校验/物化，排队时取消不会产生继续等待的blocking任务；许可只约束准备，不串行化已经启动的脚本。

实际映像协议、失败边界和验收见[锁定运行时](../../../docs/architecture/locked-runtime-images.md)及tests/http/loader/images.rs。兼容内核ABI、支持架构及隔离能力仍需满足；并非任意OS、线程型运行时或完整容器协议。

## 可验证来源与取得（L2f3a）

来源授权是独立受信配置，不从部署文件接纳公钥。GET `/api/v1/runtime-sources`（read，after/limit，默认16、1..64）分页；GET/PUT/DELETE `/api/v1/runtime-sources/{id}` 读取/修改/墓碑，写入须resources。PUT为 `{expected_revision,policy:{base_url,keys,credential_ref?,allow_loopback_http}}`，keys映射key_id到规范base64 Ed25519公钥；DELETE为 `{expected_revision}`。本地revision单调且CAS防止ABA，逻辑policy_digest只覆盖公共配置，跨机器可复用。

POST `/api/v1/runtime-acquisitions`（resources）接受 `{command_id,source,policy_digest,path,attestation}`；attestation为 `{manifest_digest,payload_digest,payload_size,key_id,signature}`。签名域为 `nofy.runtime-image.source/v1`，签名消息是按上述顺序（不含signature）的JSON数组，首项为域。GET同路径及 `/{id}`（read）返回持久元数据。最多64来源、1024命令、16次显式尝试和8MiB目录；来源API请求最多16KiB。同ID不同请求冲突，完成后精确重放不联网、不重新接纳。

来源要求规范HTTPS目录URL，禁URL凭据/查询/片段；仅显式开启的数字loopback可用HTTP。请求限授权目录的规范相对路径，不使用环境代理、重定向或隐式解压；连接/读5秒、总期30秒、最大24MiB，精确校验签名声明、载荷尺寸/SHA256及完整映像闭包。Bearer值从现有凭据后端调用时解析，可同进程轮换，不写入文件/URL/回执/日志。接纳前在来源锁内复核实际授权revision；撤销不重写已接受的历史或运行中效果。

下载最多并行2项，排队异步且可取消，不阻塞轻量元数据和运行控制。等待/传输中关闭保留Pending意图；已进入接纳提交的blocking工作可能继续完成，调用方须读取持久回执，断线不等于回滚。映像提交与回执提交是两个明确fsync边界，真实硬退出后由同一命令重试修复，不承诺HTTP GET exactly-once。下载/验证/准备期间持有许可，取消不能放出无界blocking任务。已完成命令不用于自动修复丢失的本地字节，重新取得需新命令和当前有效授权。

部署v2为`{format:"nofy.deployment/v2",system:SystemFile,runtime_sources:[AcquireImage]}`，拒绝runtime_images字段。来源最多16项，只能指向系统实际引用的manifest，重复或矛盾来源拒绝。validate离线且不解析来源凭据：完整manifest和受信签名来源锁可在空缓存纯预览；只有摘要而无manifest仍报404，已缓存但损坏的字节仍报错。import和`--system-file`必须先取得、验签并完整校验，再走编译发布，不能使用预览延迟绕过接纳。GET releases/{release}/deployment默认即来源式导出，显式mode=sources相同，mode=full拒绝。根模块、内联workflow及嵌套resource.workflow的依赖同样覆盖；最多4096模块/16层workflow，未改动的嵌套JSON不补默认字段或改变摘要。

`--source-policy-file /absolute/trust.json` 独立引导 `[{id,expected_revision,policy}]`（256KiB、最多64项）；同配置幂等，整批预检再提交，不以旧引导文件复活已撤销授权。凭据仍独立注入。`nofy-runtime-image-sign --image /absolute/image.json --key-file /absolute/seed --key-id publisher --output /absolute/attestation.json` 从仅所有者可访问的文件读取规范base64 32字节种子；不接收命令行密钥、不覆盖输出、不执行映像，stdout只返回key_id/public_key，私钥缓冲区退出时清零。

真实签名/仓库、撤销、凭据轮换、两个硬退出窗口、签名CLI/原启动入口、新目录迁移及嵌套闭包验收见tests/http/loader/sources.rs和[来源契约](../../../docs/architecture/authenticated-runtime-sources.md)。引用/卸载/GC、孤儿scratch、资源和历史迁移仍需后续阶段；不将来源取得等同完整生命周期。

## 使用租约与派生缓存回收（L2f3b1）

GET `/api/v1/loader/cache?after=&limit=8`（read）返回 `{revision,pending,plan:{after,limit,fingerprint,entries,next}}`；limit为1..16，entries包含kind/name、文件/字节计数和本地文件身份。只查看已识别的artifacts/trees、images/trees及scratch直接子项；不读源码/密钥、不执行或解压。使用中或正在维护时返回503，不能把它当成空缓存。

POST同路径（resources，最多4KiB）接受 `{command_id,expected_revision,fingerprint,after,limit}`。独占租约内重算预览，版本/指纹不符为409且不删除；先持久Pending，再把原目录移到私有trash/revision，持久记录每项source_checked后删除，最后保存Complete。GET `/api/v1/loader/cache/receipts/{revision}`（read）可在维护中读取进度。操作身份是(expected_revision,command_id)，最近64个回执可精确重放，过保留窗的旧版本明确拒绝；Pending必须先恢复原命令。断线不回滚已发生的隔离/删除；重放不清理后来重建的同名缓存。

每项最多65536节点/1GiB，最多16项；不跟随符号链接、不跨文件系统复制后删除。旧缓存在隔离区时仍占映像原1GiB解压配额，部分删除保守计费；不存在的隔离项才释放额度。可以同内核重建并继续执行旧发布，原持久objects/bin、来源、catalog、SQLite、凭据、预算、检查点和成功效果不删、不重置。

进程准备前父进程取得共享文件租约，helper在父身份/PDEATHSIG校验后独立取得并跨exec持有；seccomp禁止关闭、复制/覆盖、解锁或CLOEXEC该租约FD，禁止close_range，补齐chmodat2及全部ACL/xattr写入变体。其他FD操作与原FIOCLEX保持。取消/父退出后helper实际死亡才放出其租约。GC只在取得非阻塞独占租约后进行；大文件管理许可继续限制并发，不阻塞runs/cancel/approval/events与回执读取。

协议适用于Linux本地文件系统和已实现租约的宿主实例。升级必须先停止无该协议的旧二进制实例，不支持与未升级实例混跑后宣称已有保护；原入口、配置和业务快照保持，不迁移历史。回收只删除可重建派生物；引用观察见下一节，接纳/发布围栏、卸载与对象GC仍是后续阶段，详见[生命周期契约](../../../docs/architecture/loader-lifecycle.md)。

## 持久引用观察（L2f3b2）

POST `/api/v1/loader/references`（read，16KiB）接受`{objects:[对象键],sample_limit?:16}`。对象键为`{kind:"artifact",digest}`、`{kind:"image",digest}`或`{kind:"runtime",id,revision}`；必须1..16个且无重复，样本上限1..64。它返回每对象的来源计数、有界样本、catalog/source revision及Runtime只读事务覆盖摘要，不读取凭据或取得远端字节。

全部草稿/发布、排队与历史任务、执行记录、NextTurn、转换提议、全部有效版本和种子均纳入；检查点/子运行的已知组合绑定可解码，嵌套workflow只遍历声明位置。未完成来源取得意图保留映像，完成回执仅记录出处。用户消息、参数和结果中的相似字段不作为模块。运行库来源键统一SHA256，避免旧递归键泄露配置或输入。

已知引用为`referenced`；无匹配且存在不透明组合或不完整声明为`unknown`，否则仅为`not_observed`。未知版本、损坏、扫描超限明确失败；控制/来源revision变化返回409，不拼接不同版本。始终`deletion_authorized:false`，不能用当前观察结果批准后续删除。检查并发限2项，已开始的后台工作结束前不释放许可；独立SQLite只读事务不占原连接mutex，期限是逐行协作检查，不保证任意存储调用可抢占。

公共方法为`KernelHost::inspect_references`，API复用同一实现。真实验证见`tests/http/loader/references.rs`、`sources.rs`与跨轮会话测试；原效果/检查点/预算不改写。观察本身不授权删除；实际卸载在下述独占围栏内重新检查。

## 受管提交围栏（L2f3b3）

KernelHost在原路径接入可选CommitAdmission，Loader资源写入也加入`lifecycle/commit.lock`共享租约；来源下载不持锁，意图与取得完成提交持锁。`loader.commits.exclusive()`只排除提交，不等于持久卸载：完整卸载还须使用租约、重检引用和可恢复删除日志。维护中不排队堆积阻塞任务，管理catalog读取仍可用。

新发布与新增/变更运行声明在实际提交内复核精确制品、锁定映像和本机运行时。完整内联制品可幂等重新接纳；缺失映像/绑定拒绝，不能使用编译前缓存来承诺可用。映像完整验证按普通文件身份/纳秒mtime与ctime缓存，变化后重验，最多64项；未校验字节不进入正缓存。草稿仍可不完整，发布/执行必须独立通过验证；workflow省略schema_version保持原默认v1，显式未知版本拒绝。

catalog及运行库旁新增固定authority的admission标记；独立无策略打开与采用前已存在的SDK句柄提交均拒绝。身份不包含本机路径或凭据，不改变原快照、预算、效果与输入格式。新辅助日志以真实根租约、线程归属和冻结运行快照保存独立v1来源凭据，不能用状态字段自报owner；旧未知状态保留，不推测迁移。原未受管SDK入口仍可用。

采用协议前必须停止不识别标记的旧二进制实例；直接SQL、手改受管目录、跨主机共享/NFS锁与非合作旧实例不属于该协议保护。验证失败回滚原catalog/SQLite事务；已接纳的不可变字节可能成为无引用对象，不能宣称跨库全回滚。测试见`tests/http/loader/admission.rs`、images/sources与原会话/恢复矩阵。

## 显式持久卸载与对象GC（L2f3b4）

`KernelHost::{plan_unload,unload_objects}`与`/api/v1/loader/unload/plan`、`/api/v1/loader/unload`共用事实源，GET同路径/receipts/{revision}读取状态与回执。预览read、提交resources，请求16KiB，显式1..8个唯一artifact/image/runtime键；无路径、通配符或删除全部入口。使用与提交双独占租约内重检引用及物理指纹，referenced/unknown、漂移或扫描失败均不删除。一个runtime绑定卸载后，其他绑定仍使用的私有bin保留；不删除本机原解释器。

先持久Pending和小型准入屏障，再移除绑定、将精确对象及派生缓存rename到私有隔离区；source_checked持久后才purge，Complete最后提交。内存缓存只移除所选绑定，不清空无关已验证绑定，原发布无需worker/刷新即可继续装配。恢复不再移动已检查的源路径，保留新同名对象；最近64回执精确重放，过期命令拒绝。每次最多16部件/合计1GiB，每部件65536节点；不跟随符号链接或跨文件系统删除，不碰发布/任务/凭据/检查点/预算/效果/来源。

Pending拒绝新资源或声明提交及缓存使用/GC，防止隔离隐藏配额后再分配。普通运行查询、输入、预算结算、取消及已有根继承的辅助记录继续；继承证明只允许已保留资源键子集，不执行依赖IO。启动在开放worker前恢复原意图；旧缓存GC Pending仍可重开并用原API恢复。精确commit v1在双独占租约内升级v2，必须先停止旧实例，不改变原业务历史或authority。协议与故障窗口见[生命周期契约](../../../docs/architecture/loader-lifecycle.md#l2f3b4显式持久卸载与可恢复对象回收)，测试见`src/loader/unload/tests.rs`、`tests/http/loader/unload.rs`及原流式取消用例。历史保留迁移和完整能力平台不包含在本阶段完成声明中。

这是资源运行接纳管理，不是完整历史迁移、声明式学习/embedding装载或运行中Memory版本转换。原兼容示例与旧生产者fixture已移除；框架自身版本恢复、效果与预算连续性继续验收。

api/development.rs 提供只读能力事实；不查询任意客户端路径，不将工厂注册或 cgroup 挂载视作环境授权。
