# 常驻 Agent 管理宿主

- Owner：内核/控制面维护者。
- Read When：启动常驻内核、接控制台或修改管理 API 时。
- Update Trigger：API、权限、配置来源、调度、恢复或可管理资源变化。
- Validation：`cargo test -p nofy-agent-host`；真实回环 HTTP/SSE 与实际二进制重启用例，阶段证据见闭环计划。

这是原公共内核的可选下游宿主。网络请求负责接纳管理命令；有界后台 worker 复用原 RunSupervisor、队列、检查点、审批和持久事件。没有另一套模型或工具循环，默认公共 SDK 不依赖本包。

| 文件 | 职责 |
|---|---|
| `src/main.rs` | 命令行启动、单文件初始装载、监听与关闭 |
| `src/lib.rs` | 显式状态目录、配置/运行存储、原 Supervisor 与路由装配 |
| `src/credentials.rs`、`src/api/credentials.rs` | 独立文件凭据、CAS/墓碑、仅metadata的资源管理入口 |
| `src/auth.rs` | 环境引用式访问令牌、摘要持有与作用域检查 |
| `src/native.rs` | 稳定声明工厂与使用当前运行数据库的审批策略 |
| `src/api.rs` | 配置校验、草稿、发布、差异、应用、回滚、历史和导出 |
| `src/api/runs.rs` | 持久任务接纳、状态、事件/SSE、审批、取消、输入和恢复命令 |
| `src/worker.rs` | 并发上界、队列分页、运行占用、失败退避与任务收束 |
| `examples/workflow-system.json` | 可复用workflow作为工具/Hook/子Agent的实际单文件 |
| `examples/code-system.json` | 内联源码工具、源码Hook与模型/无模型程序的可分享文件 |
| `examples/http-system.json` | HTTP资源、可编辑工具、外部Hook方法与Agent/Tool程序的实际单文件 |
| `examples/system.json` | 实际可校验的单系统文件；连接、模型与 Prompt 均为模块 |
| `examples/access.json` | 访问令牌环境引用与权限；不包含令牌值 |
| `tests/http.rs`、`tests/http/` | 真实 API/模型协议、同进程版本变更、断线、取消、进程退出与二进制重启 |

## 启动

准备访问令牌引用文件，以及 `NOFY_KERNEL_ADMIN_TOKEN`、`NOFY_KERNEL_VIEW_TOKEN` 两个至少32字节、无空白的访问令牌。系统样例的模型凭据引用为 MODEL_TOKEN，默认从 NOFY_SECRET_MODEL_TOKEN 注入；样例模型地址和模型名必须改成当前环境可用的值。访问令牌与模型凭据是不同用途。

```sh
cargo run --locked -p nofy-agent-host -- \
  --state-dir /absolute/path/to/kernel-state \
  --access-file crates/common/nofy-agent-host/examples/access.json \
  --system-file crates/common/nofy-agent-host/examples/system.json \
  --listen 127.0.0.1:7331
```

`--system-file` 接受可编辑 SystemDocument 或锁定 SystemBundle；启动时校验、发布并按当前 generation 应用。当前已激活相同摘要时不增加记录。可以不传此参数，后续通过 API 导入文件。访问引用文件和 credential authority/prefix 是本机引导参数，不进入系统导出。更换机器使用相同的逻辑 authority，单独注入密钥；配置导入不会制造缺失的历史状态。

## API

所有 API 使用 `Authorization: Bearer <token>`，JSON 请求体上限32MiB；更小的编译、输入、队列和存储上限仍由原内核执行。身份检查在读取 JSON 前进行，未知/缺失身份返回401，缺少作用域返回403。read/edit/publish/resources/execute 独立授予，包含资源定义的写入/发布/应用同时要求 resources。当前授权覆盖该宿主的全部系统；未提供多租户隔离。

| 方法与路径 | 作用域 | 行为 |
|---|---|---|
| GET `/api/v1/modules` | read | 已安装工厂、版本、模块类型及 schema |
| GET `/api/v1/catalog` | read | 持久草稿、不可变发布、激活和应用回执 |
| POST `/api/v1/validate` | read | 单文件纯校验与冻结；不读取凭据、不执行业务 IO |
| POST `/api/v1/import` | publish | 校验并持久发布源文件或锁定文件 |
| PUT/DELETE `/api/v1/drafts/{name}` | edit | 带 revision 的草稿 CAS |
| POST `/api/v1/publish` | publish | `{draft,revision}` 发布指定草稿版本 |
| GET `/api/v1/releases/{release}` | read | 同一锁定单文件导出 |
| POST `/api/v1/plan` | read | `{system,release}` 对当前激活计算差异 |
| POST `/api/v1/apply` | publish | 原 ApplyCommand；回滚也应用历史 release |
| GET `/api/v1/systems/{name}/active`、`history` | read | 激活指针与应用历史 |
| POST `/api/v1/runs` | execute | 原子接纳 ManagedRunRequest，返回202；相同请求重放返回200 |
| GET `/api/v1/runs`、`runs/{id}` | read | 分页管理运行、原运行记录及子运行 |
| GET `/api/v1/runs/{id}/events`、`stream` | read | 持久事件页与 SSE；after/Last-Event-ID 续读 |
| GET/POST `/api/v1/runs/{id}/approvals` | read/execute | 查询运行树审批；精确原 ApprovalRequest 的不可变决定 |
| POST `/api/v1/runs/{id}/cancel` | execute | 取消未执行队列，或持久根取消并返回 cursor |
| POST `/api/v1/runs/{id}/inputs` | execute | 原 MailEnvelope；验证 root/child 收件地址和当前线程 |
| POST `/api/v1/actions` | execute | 持久接纳恢复/模型重试/子取消恢复命令 |
| GET `/api/v1/actions/{id}` | read | 命令完成结果或错误回执 |

运行请求为 `{run_id,thread_id,system,release,program,input}`，input 使用 `{text,attachments}`，仅 Agent 必填；release 是明确的已发布摘要。恢复命令为 `{command_id,run_id,command:{kind:"resume"}}`，另外支持 resume_after_cancel 的 through，以及 control 的原 RunControlCommand。嵌套控制命令的 command_id 必须相同。审批决定后再提交恢复命令，两步各自可幂等重放。

运行接纳与原队列在同一 SQLite 事务提交。客户端断开不会取消 worker；进程退出后从持久队列恢复。未知工具或模型副作用继续走原对账机制，不自动创建新的运行或重新执行。控制结果在同一根租约下确认，丢失租约时保留未确认命令。调度只读取轻量队首，分页跳过当前占用和退避任务；恢复编译放进 blocking pool。事件流关闭不影响任务；宿主关闭事件流并等待进行中的任务收束。

## 当前边界

配置目录保存 catalog.json，运行目录保存 runtime.sqlite；前者是配置后端，后者仍是当前持久调度适配器。复制锁定配置与迁移运行状态是两件事。

默认工厂支持声明模型连接、模型、静态 Prompt、审批、工具白名单、运行 Recipe/阶段和 Hook 订阅。嵌入宿主可安装已有额外工厂。通用 process 资源的外部装配、代码制品装载、完整原预设、执行中 CompositionTransition 与控制台页面仍需后续阶段；本包不能据此宣称已完成全能力动态平台。

## 运行中凭据管理（L2b1）

默认二进制使用 state-dir/credentials.json，首次缺少本地条目时可读 NOFY_SECRET_ 环境初始值。PUT `/api/v1/credentials/{reference}` 使用 `{expected_revision,value}`，DELETE 使用 `{expected_revision}`；均需resources作用域。GET `/api/v1/credentials` 仅返回revision/available及引用；不读取实际值返回给客户端。删除写入墓碑，不再回退环境旧值。编译不访问凭据，后续模型调用读取当前值，实际已发出的请求保留其原值。已配置相同逻辑authority的旧导出继续能恢复，密钥轮换不改变发布摘要。

文件仅Unix，使用0600、进程间锁、CAS、1MiB上限、1024项和单值16KiB。原子替换后目录同步失败报告可能已提交，先读metadata再决定后续CAS。文件内容受权限保护但未加密；密钥与配置/运行历史独立迁移。嵌入宿主使用同一FileCredentials装入native registry并调用with_credentials；原自定义provider可以保留，未安装管理仓库的凭据API明确不可用。

## HTTP工具和Hook（L2b2）

默认native工厂已经安装 resource.http/tool.http_connected/hook.executor。resource.http配置为 `{base_url,methods,credential_refs}`；tool.http_connected配置为 `{contract,path,method,input?,credential_ref?}`，通过标准connection依赖指向HTTP资源。Hook复用这一个工具Pack，经hook.executor与hook.subscription绑定事件。实际可校验示例为examples/http-system.json；服务端Hook接收完整HookEvent，并返回原HookDecision，如 `{decision:"patch",payload:完整新payload}`。

工厂只解析配置和URL，不创建客户端、读密钥或请求服务。调用时惰性初始化原HttpConnection，并复用原HttpToolFactory/dispatch 的映射、流取消、timeout和输出限制；相同编译资源中的工具共享客户端。凭据来源与模型是同一逻辑authority。添加无关HTTP连接不改变已有程序identity，修改路径/方法等配置需发布新版本；旧已发布程序保持旧配置，凭据值按后续实际调用更新。

HTTP基址无inline credentials/query/fragment，必须目录形式；输入不能覆盖URL/方法/密钥引用，路径不能跳出基址，禁止重定向与环境代理。资源写入/发布/应用需要resources作用域。当前这支持外部服务自定义方法；进程代码、全部原能力和执行中组合转换继续后续阶段。

## 内联源码方法（L2b3）

默认宿主启用executors/rhai并注册tool.rhai，公共executors包默认不启用该feature。配置为 `{contract,source,input?,max_operations?}`，源码上限1MiB，max_operations默认100000、范围1..10000000，未知配置拒绝。方法用args接收映射后的JSON，可返回最终表达式或调用complete(value)，输出继续经过原contract映射/schema/字节限制。单文件examples/code-system.json包含无模型计算与before_model源码Hook。

语法发布时编译，计算只在实际调用的blocking pool中运行。方法profile关闭import/eval/print/debug，未安装Agent/工具/文件/网络宿主函数。固定调用深度16、表达式128/64、变量/函数128、字符串递归总量1MiB、数组/Map递归总量各4096，并响应timeout/父取消/future丢弃。限制是进程内VM限制，不是OS内存隔离。宿主密钥与capabilities不作为脚本全局提供。原workflow脚本编排入口保持，复杂编排和其Agent选项继续独立阶段。

## 可复用workflow（L2c）

resource.workflow配置`{document:WorkflowDocument,bindings?:{alias:ModuleKind}}`，标准dependencies连接alias到已有模块。只获得声明依赖/传递依赖与强制floor，其他系统定义不自动可见。编译后校验来源和资源身份。tool.workflow_connected配置`{name,description?}`、hook.workflow_connected配置`{}`，依赖workflow:Resource；订阅再引用Hook handler。它们复用原workflow执行和控制器，支持图中Agent、Tool及原有子图/循环等能力。

GET模块schema之外，POST `/api/v1/modules/dependencies` 接受`{factory,config}`，以read作用域纯查询固定/动态依赖名及类型，供控制台连线。内联WorkflowProgram.document.modules也纳入资源权限检查，不能经嵌套定义绕过resources。workflow-system.json已验证无模型工具、真实模型前Hook、子Agent、源码更新/旧版本和跨目录锁重建；运行参数/人工响应的管理扩展继续下一阶段。

## 每次运行的参数（L2d1）

GET `/api/v1/releases/{release}/programs` 以read作用域返回每个程序的kind、accepts_message、parameters_schema和default_parameters。Agent仍使用input消息；Tool使用parameters作为完整arguments，根workflow使用parameters作为入口输入，Event使用parameters作为payload。省略parameters保留发布默认值，显式null是独立的实际输入。静态schema与1MiB上限在接纳前校验；动态ToolSource的schema仍由原执行边界检查。

例如同一do_work发布可接收 `{run_id:"calculation-9",thread_id:"calculation-9",system:"portable-assistant",release:"实际发布摘要",program:"do_work",parameters:{value:9}}`。参数在原任务事务内连同真实ExecutionSnapshot冻结；恢复不读取后来配置的默认值。同run_id重发相同请求回放回执，改变参数会拒绝。独立任务使用独立thread_id；同线程改变组合仍受原身份保护约束，运行中组合转换属于L3。

## 人工等待与响应（L2d2）

GET `/api/v1/runs/{id}` 的children中，kind为workflow_human的run_id是响应目标。POST `/api/v1/actions` 使用command.kind=human、target_run_id、workflow_path、expected_request及value；command_id仍在外层。根workflow路径为空；连接模块workflow使用其冻结Resource引用路径。客户端不指定原始检查点键或线程归属。响应需要execute作用域，结果通过actions/{id}查询；错误响应也会结束命令，不堵塞后续合法操作。

原Human节点决定响应schema与当前request，已接受决策和命令ID均不可变。恢复走原根监督器、Hook源事件和图检查点；根workflow、模块workflow、多层模块以及模型前Hook中的等待均已实测。真实HTTP效果计数、进程直接退出、人工决策已保存及管理回执丢失边界验证不会重复既有业务效果。本阶段未开放任意原始检查点读写，也未完成停止/放弃/全部未知效果对账。

## 业务事件生产者（L2d3）

event.producer的config为`{events:[{name,payload_schema,deny?,pause?,patch?,stop?}]}`，owner由模块reference绑定。不能上传owner、声明原生命周期事件名或占用nofy.runtime。hook.owned_subscription的config复用HookRule，显式依赖producer:EventProducer和handler:HookHandler；订阅只能选择该producer声明的事件。旧hook.subscription保持原身份和配置。

examples/event-system.json可直接导入：它定义business.received事件、源码回调与EventProgram，默认payload.value=7输出14；POST runs的parameters.value=9输出18。全部沿原EventProgram、HookBus和journal，不调用模型。锁文件可在另一state-dir恢复；业务事件中的workflow Human等待也可通过原管理命令响应，保留原owner和源事件。

## 子工具对账（L2d4a）

GET `/api/v1/runs/{id}/recovery?limit=100&after=子运行ID` 需要read，返回schema_version、targets和next；候选页1..256条，返回体8MiB。targets包含root_run_id、run_id、thread_id、kind、checkpoint_revision、model_sequence和完整call。状态视图会变化，执行时仍校验根/子归属、组合和完整待执行操作。图控制标记不作为候选；已接纳的可恢复控制器仍由原执行边界拒绝外部效果对账，应选择其内部原语。

POST `/api/v1/actions` 使用command.kind=reconcile_child，receipt为原ChildReconciliation：child_run_id、必须提供的model_sequence、call、result和is_error。命令持久接纳后，在原根租约内保存原生证据，再恢复原根；查询actions/{id}取得最终回执。旧SDK的reconcile_program_child仍可用。不确定效果由操作员证据确认，进程退出/重复命令均已用真实HTTP验证不会重发既有请求。模型未知结果及停止/放弃继续后续阶段。

## 预算资源（L2e1）

默认常驻宿主在打开原runtime.sqlite后安装resource.budget与governance.budget_connected。前者config为空对象，绑定同一账本；后者以budget:Resource为标准依赖，配置limits/retry。限制字段和重试约束复用原预算引擎；配置/编译只绑定句柄，不产生enroll记录。可运行单文件见examples/budget-system.json。

资源身份来自可信逻辑authority、声明reference、ceiling、retry ceiling和持久化语义，不写本机数据库路径；同一配置锁已验证跨state-dir恢复。配置导出不携带历史账本。实际调用仍通过原storage_identity与根监督器校验，再使用原租约围栏做预留/结算；逻辑同名不能使用另一个物理DB的账本。旧InstalledBudget::install/GovernanceFactory身份保持兼容。

预算可作为required_governance约束整个系统。真实HTTP验证workflow额度用尽后阻止后续效果，resume保持已消费/预留额度。该配置发布仍遵守既有执行快照；运行中的预算变更属于后续组合转换。

## 根工具恢复（L2e2）

GET `/api/v1/runs/{id}/recovery/root` 需要read，返回根待处理调用或null（run_id、thread_id、checkpoint_revision、model_sequence、call），原子运行分页API保留。投影信息为候选，接受证据时在原根租约下重新校验冻结组合、运行归属和完整操作。

POST `/api/v1/actions` 的command.kind=reconcile_root_tool，receipt必须包含model_sequence、完整call、result、is_error；需要execute。使用全局command_id幂等接纳和原证据表，结果不可覆盖。Agent/Tool根恢复后沿原循环继续，无模型Tool仍不请求模型；启用预算时结算既有预留且不重置消耗。根workflow/Event及Tool包裹的可恢复控制器需定位实际原语子运行，不能替换控制器结果。

## 治理模型恢复（L2e3）

GET `/api/v1/runs/{root}/recovery/models?target_run_id=Agent运行ID` 需要read，缺省目标为根，返回原生待处理尝试。目标可为根Agent或记录的Agent后代；票据包含thread/run、operation/scope、请求指纹、generation及attempt，另返回原预留、unbounded_tokens和证据接纳状态。

POST `/api/v1/actions` 的command.kind=reconcile_model，receipt为ticket与result。result.kind=completed携带原ModelResponse；kind=failed携带原ModelFailure。execute作用域、原管理队列、根租约、检查点归属与不可覆盖journal共同限定接纳；之后由原采样边界使用证据，真实预算回执始终优先。费用按原上界保守结算，失败继续原显式/策略重试，重放不清空消耗。

此API管理已有治理模型派发意图；未治理旧入口尚未获得相同崩溃对账保证。不会因提交result而绕过权限、上下文变化或预算期限。

examples/model-recovery-system.json组合真实Sampler连接、原持久预算、提示词及源码工具。使用时设置实际提供方URL/model、可信request_limits与MODEL_TOKEN引用；令牌值仍通过凭据后端注入。它与普通系统使用相同导入/发布/执行接口，无需为对账再编译一个Agent包。

## 无预算日志绑定（L2e4）
