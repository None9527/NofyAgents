# 工具执行公共契约

统一工具发现、调用、取消、上下文、流和结果渲染接口，不拥有工作区绑定、产品预设配置或用户界面开关。可选的调用信息由调用方通过TypedExtensions显式注入；不存在工具侧读取旧产品配置的默认路径。

- Owner：工具运行时维护者。
- Read When：实现工具来源、dispatch、流式结果或调用上下文时。
- Update Trigger：公共Tool契约、错误、进度、模型内容及依赖边界变化。
- Validation：`cargo test --locked --offline -p nofy-tool-runtime`及`scripts/verify-framework-boundaries.py`。

| 文件 | 职责 |
|---|---|
| `src/context.rs` | 类型扩展存储、调用/发现上下文与独立cwd/版本/trace/session/取消标识 |
| `src/tool.rs`、`src/dispatch.rs` | 工具/工具族/分派接口与结果流 |
| `src/error.rs` | 规范工具错误及直接Serde，调试source不序列化，无旧线协议投影 |
| `src/streaming.rs` | 流式分块与部分结果 |
| `src/render.rs` | 中立模型内容块提取；不生成UI卡片或识别旧产品结果包装 |
| `src/search.rs` | 工具搜索快照与索引接口 |
| `tests/` | 上下文、动态工具、流、取消、错误、三字段输出及搜索契约回归 |

CLEAN4移除工作区侧带和旧gRPC依赖；CLEAN4b移除业务通知、UI类型和旧结果特判，TypedToolOutput严格保留tool_id/value/model_output，业务value内容不受限。CLEAN4c删除ToolErrorWire桥接和RenderLimited业务分类，规范ToolError直接序列化；无兼容别名。普通内部依赖仍仅有tool-runtime、tool-protocol、tool-types三个包；边界检查同时拒绝普通/构建边引入旧工作区gRPC协议。tool-protocol已收敛为身份/能力叶子包，旧工程源码树仍待清理。
