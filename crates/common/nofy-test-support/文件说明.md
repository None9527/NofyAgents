# 框架协议测试夹具

CLEAN5a从codegen迁入common；所有Rust源、原SSE帧、包名/API保持原字节，旧路径不留转发。它是测试支持而非Agent运行依赖，迁移须回归契约与实际Host，不能把搬目录当作最终旧树清理完成。

本包提供三类测试支持：目标Host契约/恢复测试使用的三种Chat Completions SSE帧；测试在本机缺少所需能力时的**可见跳过**（`capability`）；以及不假定Unix路径的夹具（`fixture`）。不包含Agent、模型实现、ACP/stdio/PTY宿主、子进程管理、环境覆写或旧产品测试入口。夹具中的模型名与固定usage是测试输入，不是真实服务或用量证据；真实模型验收独立使用用户配置连接。

- Owner：框架协议测试维护者。
- Read When：实现确定性流式协议或Host恢复用例时。
- Update Trigger：SSE帧、工具调用参数、保留函数或依赖边界变化。
- Validation：`cargo test --locked --offline -p nofy-test-support`、完整Host回归与`scripts/verify-framework-boundaries.py`。
- 统计一次运行的跳过：对测试输出执行`grep -c 'nofy-skip:'`；每条形如`nofy-skip: <测试路径> | needs <能力或程序> | <原因>`。

| 文件 | 职责 |
|---|---|
| src/lib.rs | 导出sse、capability、fixture模块，禁止unsafe |
| src/sse.rs | 三种帧生成函数、无名SseEvent数据帧及Axum转换 |
| src/capability.rs | `require_capability`／`require_level`／`require_program`／`skip`／`skip_unless`、宏`require_capability!`与`require_program!`、`probe_from_report`。按`nofy-isolation`的探针（`Probe`）或机器上是否有某程序决定测试能否继续；不能时向进程stderr（绕过测试框架的输出捕获，通过的测试也可见）写一行以`nofy-skip:`开头的跳过信息并提前返回。不按操作系统名推断能力。环境变量`NOFY_SKIP_REPORT`指向文件时每条跳过同时追加到该文件 |
| src/fixture.rs | `canonical_tempdir()`：路径已规范化（`std::fs::canonicalize`，与Host对状态目录的做法一致）的临时目录。macOS的临时目录在`/var`（`/private/var`的链接）、Windows运行器是`RUNNER~1`短名，内核有意拒绝路径中的链接并在账本中记录规范路径，未规范化的夹具会因夹具自身的原因失败 |
| tests/sse_contract.rs | 空白/Unicode/空文本、调用原始参数和帧终止顺序；Axum线编码一致性 |

普通/构建内部依赖仅本包自身与平台中立的叶子包`nofy-isolation`（只依赖serde与thiserror，供测试按探针跳过；`scripts/verify-framework-boundaries.py`已列入允许项），直接第三方依赖为Axum、serde_json和tempfile；测试代码另用的Tokio/futures-util放dev。CLEAN4d在原实现的三项契约通过后保留同一帧生成逻辑，删除十二个旧宿主/产品服务模块，无旧API别名。Host仍实际需要tty-utils执行原生进程组取消与隔离，该中立安全能力不等于本次淘汰的PTY测试宿主。全源码树和完整唯一预设仍需后续交付。
