# Grok Build Desktop · 产品设计（PRD v1）

> 基于 nofy 内核的自主工作桌面端。参考范式：ZCode 3.7.6（单会话深度工作台）
> + Orca 1.4（多 agent 舰队总览）。技术规格见 `zcode-uiux-spec.md`、`orca-spec.md`。

## 0 一句话定位

**给 10x builder 的"自主工作 Mission Control"**：把长时运行的 AI 任务当成
可排队、可审批、可回滚、可复盘的"异步同事"来管理——单任务时是安静的深度
工作台（ZCode 范式），多任务/多代理时是舰队总览（Orca 范式），两者一键切换。

不是：聊天机器人套壳、IDE 替代品、云端 SaaS 控制台。

## 1 愿景与非目标

愿景：用户"布置工作→离开→回来验收"。产品价值 = 无人值守完成率 × 验收效率。

非目标（v1 明确不做）：
- 不做代码编辑器/IDE 分屏编辑（只读审查 + 外部打开）；
- 不做多模型并排竞赛（Orca 的 worktree 赛马）——nofy 内核是单 daemon 多会话，
  并发来自子代理/委托，不来自 git worktree 隔离；
- 不做账户/订阅/算力套餐界面（本地 daemon 无账户体系，诚实降级）；
- 不做插件市场（MCP 已够用）。

## 2 用户与场景

| Persona | 特征 | 核心 JTBD |
|---|---|---|
| P1 自主工程师 | 每天跑 5–20 个 agent 任务，习惯排队 | "睡前布置，早起验收"：队列+无人值守+晨间复盘 |
| P2 技术负责人 | 关心 token 成本与风险 | 审批闸门、用量可视、变更审查后合并 |
| P3 偶尔使用者 | 把 agent 当搜索引擎用 | 零配置单会话，别让我学概念 |

关键场景：
1. **布置**：首页 composer 一句话起任务；@文件 #会话 /命令 补上下文。
2. **离开**：任务排队/后台跑；看板总览谁在干活、谁卡住等我。
3. **被叫回**：elicitation/审批/完成未读 → 系统级提醒 + 看板 "需要你" 列。
4. **验收**：变更审查（diff + 回滚点）、子代理产物、token 账单；一键 fork 重试。
5. **routine**：自动化（定时/闲时）+ 监视器（日志/CI 守护）无人值守。

## 3 nofy 内核能力清单（产品边界）

已具备（后端真实可用）：会话 CRUD/流式、工具调用与审批、子代理、工作流
（panel/lineage）、委托后台 run、监视器、队列消息、回滚点（rewind）、
elicitation、调度（schedule CRUD）、MCP CRUD、技能、用量统计（token/上下文）、
git 状态、终端 exec、远程配对码、多传输（ACP-WS / Electron IPC / mock）。
约束：单工作区单 daemon 实例（?ws= 切换）；无账户；无 worktree 隔离。

## 4 概念模型（用户可见对象）

| 对象 | 说明 | 来源映射 |
|---|---|---|
| 工作区 Workspace | 一个项目目录 + 其 daemon 连接 | ZCode workspace |
| 任务 Task | 一次会话（含轮次/工具/产物） | ZCode task / Orca worktree-tab |
| 运行 Run | 任务内的活动执行单元：主代理/子代理/委托/工作流面板 | Orca agent card |
| 审批 Request | elicitation/工具确认/计划批准 | ZCode confirm + Orca attention |
| 变更 ChangeSet | 一轮产生的文件 diff + 回滚点 | ZCode change summary |
| 例程 Routine | 定时/闲时自动化 + 监视器 | ZCode automations + Orca automations |
| 能力 Capability | 技能 / MCP / 命令 / 模型 | 两者 settings |

状态语义（全产品统一，抄 Orca 映射表）：
working=spinner 绿 / waiting·approval=琥珀问号 / done 未读=绿点加粗 /
done 已读=灰 / error=红点 / monitoring=黄无线电。**颜色只表状态**（设计纪律）。

## 5 产品形态与外壳蓝图

桌面端（Electron）为主，Web 为远程查看形态（配对连接，能力诚实降级）。

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏浮层：[logo⇄侧栏][←][→][+新任务]      [终端][侧栏][⌄菜单|−□×] │ 36-48px
├────────────┬─────────────────────────────────┬───────────────┤
│ 侧栏        │  会话工作台                      │ 上下文轨       │
│ 导航4项     │  全宽头：面包屑/标题/变更pill/git   │ (活动栏切换)   │
│ 分段 组|项目 │  ─────────────────────────────  │  摘要/子代理树  │
│ 任务列表    │  轮次流（用户行border-b/助手md/     │  git 审查     │
│  (状态点语义)│   工具卡/审批内联/轮级动作悬停)     │  AiVault式    │
│ ─────────  │  composer（@#/命令/模型/effort）   │  会话历史库    │
│ 页脚 用户⌄  │  dock：终端|浏览器|审查（可分屏）   │               │
├────────────┴─────────────────────────────────┴───────────────┤
│ 状态栏24px：daemon健康 · token用量名册⌄ · 监视器活动 · 配对码 · 缩放 │
└──────────────────────────────────────────────────────────────┘
  + Agent 看板抽屉（Ctrl+Shift+D，从侧栏缘展开，非模态）：需要你/进行中/完成/空闲
  + 命令面板 Ctrl+P（分区+模糊质量阶梯）· 跳转 Ctrl+K 搜索 · Ctrl+F 会话内查找
```

chrome 纪律（两参考共识）：单色安静；灰阶承载 chrome，颜色只留给状态；
非模态 companion 优先于模态；portal 弹层预留窗口控制区；终端聚焦释放拖拽区。

## 7 关键流程（含空/错/降级态）

1. **起任务**：首页→composer→Enter。错态：无工作区→composer 禁用+引导选择；
   daemon 断→顶部横幅"重连"，composer 只读。
2. **排队**：运行中发送→入队芯片可见；轮结束自动排空（已有后端语义）。
3. **审批**：elicitation/工具确认内联卡（允许/拒绝/查看输入）；超时不假设默认。
4. **回滚/编辑**：轮级 ↺（回滚点）与 ✎（确认→回滚+预填重发）；冲突文件列表警告。
5. **验收**：变更 pill/git chip→审查 dock：文件列表→diff→单文件回滚；外部打开。
6. **舰队总览**：Ctrl+Shift+D 看板；"需要你"卡→reveal 跳会话并 flash 定位；ack=已读。
7. **例程**：自动化页创建定时（cron+goal）；状态栏显示下次触发；失败→看板 attention。
8. **远程查看**：Web 输入配对码→只读总览+审批（不发 prompt 的权限可配）。

降级哲学（抄 Orca 反模式清查）：连接瞬态显示"connecting 琥珀"而非"disconnected
灰"；**状态翻转不清空已载数据**（"Last known: N tasks" 陈旧保留）；能力缺失给
诚实 toast，不画死按钮。

## 8 设计语言（ distilled ）

- 令牌成对、color-mix 派生色、git 装饰色镜像 VS Code、三级阴影封顶（Zcode 像素值
  与 Orca token 表已并存于两份 spec，取 Orca 纪律 + ZCode 暗色像素值）。
- 字号 11/12/13/14 四档；11px 仅大写元信息；Geist/系统 sans + mono 表路径。
- 列表行三态 + data-current；键盘选中用 mix+inset ring。
- 原语分叉表直接采用 Orca §2.5（Tooltip/HoverCard/Sheet/Dialog 语义不混用）。

## 9 路线图

- **Phase 1（现状→2 周）**：P0 全绿 + 状态点语义统一 + 看板子代理展开。
  （P0 大部分已实现，见实现清单）
- **Phase 2（+3 周）**：状态栏、上下文轨四标签、命令面板升级、设置双栏、通知。
- **Phase 3（+4 周）**：Web 远程配对、引导、终端分屏、quick commands、用量账单页。

## 10 成功指标

- 无人值守完成率（任务完成且全程零审批/零追问）↑
- 叫回响应时长（attention→reveal）↓
- 验收时长（完成→ack/合并）↓
- 周活跃任务数、例程占比（routine/total）↑
- 降级事件中的用户流失 = 0（诚实降级验收）

## 11 风险与取舍

- 单 daemon 并发上限→看板"进行中"需显示排队位（队列语义外显）。
- 无 worktree 隔离→多任务改同仓会冲突：审查 dock 必须强（回滚点兜底）。
- Electron 与 Web 能力差→所有入口先过"回退代理"设计评审，禁死按钮。
- 概念密度（Run/Routine/ChangeSet）→v1 界面文案只露"任务/例程/变更"，其余进文档。
