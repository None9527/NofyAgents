# Grok Build · 深度设计 v2（第一性原理推导）

> v1（product-prd.md）是功能拼盘，作废其 IA 部分，保留非目标与指标。
> 本文件从 nofy 内核的物理事实出发推导产品形态，而不是从两个参考应用做平均。

---

## 1 内核的物理事实（一切设计的公理）

观察 nofy daemon 的 API 面，得到六条不可辩驳的事实：

F1 **daemon 先于且长于任何 UI**。任务在 UI 关闭后继续运行；UI 只是众多
   附着客户端之一（CLI/web/Electron/远程配对）。
F2 **会话是事件日志，不是聊天**。turn/工具调用/elicitation/回滚点/子代理/委托/
   监视器事件都进日志；多客户端渲染同一日志。
F3 **注意力是结构化协议**。elicitation/create、工具审批、队列变更都是
   机器可读的"请求注意"事件，带类型与载荷。
F4 **时间是一等公民**。queue=近未来，schedule=远未来，monitor=连续，
   delegation=异步，rewind=过去，lastSeen=观察点。
F5 **安全网内建于内核**。每轮 rewind 点=文件+对话的检查点；autonomy 因此
   可以是旋钮而不是信仰。
F6 **编排是图不是列表**。主代理→子代理→委托→监视器，构成活的执行谱系。

ZCode 和 Orca 都违反 F1（它们拥有并_spawn_ agent，关应用即杀进程），所以它们
的隐喻只能是"驾驶舱"。nofy 的隐喻必须不同。

## 2 隐喻与三动词

**隐喻：一个始终在岗的远程团队的工作台。** 你不是在"用工具"，是在
**管理一组自主同事**：布置工作、偶尔被请示、回来验收。

由此产品的全部交互收敛为三个动词：

| 动词 | 含义 | 内核支撑 |
|---|---|---|
| **Assign 布置** | 把意图变成可执行的工作单 | session/new + prompt + mode/confirm/effort |
| **Observe 观察** | 不打扰地知晓进展 | 事件日志 + 状态钩子 + stats |
| **Adjudicate 裁决** | 在被请求时做最小决策 | elicitation/审批/rewind/fork/ack |

**设计判据**：任何界面元素若不服役于这三个动词之一，就是噪音，删。
（ZCode 的 hero 插画、Orca 的 pet 状态段，在我们这里都不存在。）

## 3 注意力总线（产品的心脏）

稀缺资源是注意力不是算力。F3 允许我们做两个参考都没做到的事：
**把"agent 找你"建成一条有优先级的中断总线**，而不是散落的红点。

中断分四级（默认不升级，可被用户提升）：
- **L0 记录**：完成已读、FYI 监视器事件 → 只进日志/摘要
- **L1 瞥见**：状态栏计数、看板列移动、侧栏状态点 →  Peripheral vision
- **L2 召唤**：看板"需要你"列、未读加粗、tray 徽章+1 → 主动来看
- **L3 打断**：系统通知+声音，仅用于"阻塞且等待有成本"的审批/elicitation

每个中断卡携带：**等待时长**（SLA 可见）、**等待成本**（agent 阻塞=算力闲置）、
**一键动作**（允许/拒绝/稍后/降级为 L1）。裁决永远在原地完成，不强制跳转；
需要上下文时才展开到会话。

> 这是"完美桌面公民"的关键：打断的粒度与升级权在用户手里，且默认安静。

## 4 时间脊柱与"离开-回来"循环

F1+F4 推出杀手场景：**你不在时世界继续，回来时产品替你补课。**

- 全局**晨报/回来摘要**：附着瞬间计算 lastSeen 之后的事件，按任务聚合成
  digest 卡（完成 3 / 请示 1 / 失败 1 / 花费 0.4M tok），每条带原地动作。
  这不是通知列表——是**带判决按钮的交接简报**。
- 任务内**时间脊柱**：会话不是气泡流，是一条事件脊柱；左侧刻度可 scrub；
  工具/子代理/检查点是脊柱上的节点类型；"我不在的区间"自动折叠成摘要段，
  点击展开。
- **监视器与例程**是"永远在线的同事"：它们在脊柱之外拥有自己的心跳行，
  出现在状态栏与看板 idle/monitoring 列。

ZCode 的会话是"聊天记录"，Orca 的是"终端回放"；我们的是**可判决的工作日志**。

## 5 信任旋钮与安全网外显

F5 推出 autonomy 不是设置项而是**可见的契约**：

四级旋钮：L1 每步批准 / L2 变更确认 / L3 自动+检查点 / L4 全自主。
每个任务头显示：当前级 + **回滚覆盖率**（"本任务 12 轮全部可回滚"）。
**信任校准循环**：连续 N 轮零回滚零驳回 → 产品建议升级（"提升到 L3？"）；
发生回滚 → 自动建议降级。autonomy 由此成为被数据校准的信任，而非胆量。

这把 nofy 的 rewind 从"恢复工具"升格为**产品核心资产**：它使 L3/L4 可授予。

## 6 工作单 composer（Assign 的仪式）

意图进入内核前应被结构化为**工作单**，composer 实时解析并显示芯片：
`[@文件×2] [#参考会话] [模式:build] [autonomy:L2] [effort:高] [预算:0.5M tok]`
未识别部分=自由文本目标。发送=**派遣**（按钮文案即动词）。
预算芯片=F6 的成本信封入口：软上限触发 L1 提醒，硬上限触发 L3。

这消除自主系统最大的焦虑源：我以为它懂了 / 我以为它不会超支。

## 7 执行谱系视图（Observe 的深端）

F6：任务详情 = 双模：
- **文档模**（默认）：时间脊柱会话；
- **谱系模**：主代理为根的活组织图——子代理/委托/工作流面板为节点，
  状态光晕同看板语义；节点可折叠、可跳转其子会话、可单独 ack/fork。
"看一个任务"因此等于"巡视一个小组"。Orca 的 Agent Map 是跨仓库空间布局；
我们的谱系是**任务内组织图**，数据更真（内核直接给 lineage）。

## 8 三个表面（桌面公民形态）

F1 推出 UI 必须多形态且**渲染日志而非拥有状态**（F2 的工程纪律：所有动作
写回事件，任何客户端附着即同步——手机批准、桌面看见）。

| 表面 | 形态 | 服役动词 |
|---|---|---|
| **Companion** | tray 图标+浮动药丸（"3 进行 · 1 等你"），popover=迷你注意力总线 | Observe + 轻量 Adjudicate |
| **Console** | 主窗口：侧栏舰队 / 中央三模工作区 / 右注意力轨 / dock / 状态栏 / 回来摘要 | 全部，重裁决与深观察 |
| **Remote** | Web 配对附着：只读观察+裁决，能力诚实降级（回退代理语义） | Observe + Adjudicate |

你在 IDE 里写代码时，Companion 浮着舰队；需要判决时一点直达 Console 的
对应脊柱位置。**主窗口不再是"agent 的家"，而是"你的裁决庭"。**

**Companion 表面**。

## 10 关键流程（v2 重写）

1 **晨间回来**：附着→摘要条"离开 14h：完成4·请示1·失败1·0.9M tok"→逐条原地
  判决（合并/重跑/批准/ack）→清空后自动收起。全程不离开当前视图。
2 **派遣**：composer 输入→芯片实时成形→调 autonomy 旋钮→派遣→任务进看板
  Working→Companion 药丸 +1→回到 IDE 继续自己的工作。
3 **被请示**：L3 通知"X 等你决定（已等 2m，闲置成本…）"→点击→Companion popover
  内联 elicitation 卡→允许→agent 即刻继续→事件进脊柱。
4 **验收**：完成 L2→看板 Done 绿→reveal→审查模 diff→逐文件回滚或全收→ack 沉灰。
5 **放权**：L2 任务连续 12 轮零回滚→头部提示"提升 L3？"→确认→旋钮变化写进日志
  （跨客户端可见）。
6 **例程值守**：schedule/monitor 心跳在状态栏；失败→L2 进注意力轨；连续失败 3 次
  →L3（升级规则可见可改）。

## 11 设计语言与纪律（继承两 spec，加三条本征纪律）

- 单色安静、颜色只表状态、color-mix 派生、git 色镜像 VS Code、三级阴影封顶、
  行三态+data-current、原语语义不混用（orca-spec §2）。
- **D1 不拥有状态，渲染日志**：任何按钮先问"它写哪个事件"。
- **D2 不打无准备的断**：中断必带 SLA+成本+一键动作，否则降级。
- **D3 不画死按钮**：能力缺失=诚实文案；瞬态=琥珀 connecting；翻转不清数据。

## 12 非目标（v2 加固）

不做：worktree 赛马、内嵌代码编辑、账户/套餐、插件市场、空间化 agent 地图
（谱系模已覆盖其价值，且数据更真）、语音、pet。

## 13 可行性核对（每个新概念→内核现成能力）

| 概念 | 内核支撑 | 现状 |
|---|---|---|
| 注意力总线 | elicitation/create、审批、queue/changed、monitor 事件 | 事件已有，分级/SLA 为纯前端 |
| 回来摘要 | lastSeen(taskmeta) + 事件日志 diff | 前端可算，无需后端改 |
| 时间脊柱/区间折叠 | turns+toolCalls+stats.summary | 前端渲染层 |
| autonomy 旋钮 | mode/confirm 参数 + rewind 点覆盖检测 | 已有参数，旋钮=前端契约 |
| 信任校准建议 | rewind/execute 历史 + 驳回计数 | 前端统计 |
| 工作单芯片 | @/#//、mode、effort、set_model | 已部分实现，补预算芯片 |
| 谱系模 | 子代理行、委托 run、工作流 panel | 数据在会话内，前端建图 |
| Companion | Electron Tray + 状态聚合 | 新增表面，纯前端 |
| 预算信封 | stats.usage/contextWindow | 前端阈值 |
| Remote 裁决 | 配对码 + ACP-WS | 已有传输 |

**结论：v2 的全部"新"体验都是内核既有事件的更优渲染与契约化——没有幻想功能。**

## 14 路线（对齐现实现）

P0 已绿：外壳/侧栏/首页/会话/dock/看板雏形。
Phase-2（注意力与时间）：注意力轨+中断分级、回来摘要条、脊柱渲染、状态栏舰队脉搏。
Phase-3（契约与谱系）：autonomy 旋钮+回滚覆盖、工作单芯片、谱系模、Companion。
Phase-4（远程与校准）：Remote 裁决、信任校准循环、预算信封告警。

---
*判据回顾：assign / observe / adjudicate 之外无界面；打断的权力属于用户；
安全网外显使 autonomy 可授予；UI 渲染日志而不拥有状态。*
