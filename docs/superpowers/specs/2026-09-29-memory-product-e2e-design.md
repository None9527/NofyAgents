# Nofy 记忆产品闭环与 E2E 设计

## 目标

统一记忆已经完成单系统重构，服务边界内也有迁移、捕获、搜索、整理、纠正、忘记和恢复测试。本设计补齐最后一层产品证据：从真实 `nofy` 二进制启动开始，经过 ACP 会话、模型请求和工具调用、持久化、下一次推理、进程重启与新会话，验证用户实际体验到的写入和引用行为。

本项目不增加第二套记忆实现，不恢复旧 Grok 记忆目录，也不把未来知识库接入当前记忆系统。

## 方案选择

### 采用：真实二进制、确定性模型、用户可见契约

测试启动真实 `nofy` 子进程，使用隔离的 `NOFY_HOME` 和 mock inference server，通过 ACP 或 headless 公共入口驱动会话。测试只在外部边界准备数据和观察结果，不直接调用 `NofyMemoryService` 来代替产品链路。

优点是能够同时覆盖配置、composition root、工具注册、请求注入、落盘、重启恢复和用户回执；mock 模型让结果可重复，也不需要真实账户或网络模型。

### 未采用：修补旧 Python 集成脚本

旧脚本覆盖面广，但依赖 `xai-grok-pager`、`.grok`、`GROK_MEMORY` 和旧存储布局。逐项替换名称仍会保留对 SQLite 表和内部文件的直接断言，使测试验证实现细节而非当前产品契约。

### 未采用：只扩充 Rust 服务集成测试

现有 `nofy-memory` 测试已经充分覆盖公共服务及故障恢复。继续在同一层增加测试无法发现二进制没有注册工具、`NOFY_HOME` 没有传递、模型请求没有注入 snapshot、会话关闭没有落盘等接线问题。

## 用户体验契约

### 安静读取

系统按需检索记忆。没有实际影响本次回答的记忆，不产生用户可见标记。检索失败时不伪造引用，也不把内部错误、文件路径或数据库信息交给模型。

当记忆确实参与回答时，在回答正文之后显示轻量入口：

> 基于记忆：当前项目 · 部署约定

入口不插入正文段落，不打断答案阅读。展开后显示事实摘要、作用范围、来源类型或来源对话时间，以及“纠正”和“忘记”动作。普通界面不显示路径、hash、revision、operation ID、observation、topic 或 rollout 等实现术语。

### 显式写入

用户明确说“记住……”时，主助手可以先给出正常回答，但“已记住”回执必须出现在记忆服务完成规范写入、索引更新和 generation 推进之后。推荐放在回答末尾：

> 已记住到“关于我”：默认使用 Rust。撤销

如果写入失败，不能显示成功回执；应给出简洁、可行动的失败说明。敏感非凭据信息写入前确认，凭据和 secret 即使用户确认也拒绝。

### 自动学习

自动捕获和整理在答案展示之后运行，不位于回答关键路径，不逐轮通知。只有持续失败、迁移完成或需要用户决定时才提示。自动学习关闭后，显式记住、纠正和忘记仍然可用。

### 当前指令优先

记忆是历史上下文，不是高优先级指令。当前用户指令高于当前项目记忆，当前项目明确规则高于“关于我”的默认偏好。被 promptware 扫描阻断的内容不得原样进入提示词或引用入口。

## 产品数据流

### 写入链

1. 用户在主助手会话中明确提出记忆意图。
2. 模型调用唯一的 `memory_write` 公共工具，或 Shell 的等价显式命令入口。
3. `MemoryService` 完成规范对象写入、派生索引更新与 generation 提交。
4. 工具返回用户可读 receipt；只有此时 UI/回答才能显示“已记住”。
5. 当前会话在下一次模型推理前刷新冻结 snapshot。
6. 短期“撤销”只针对本次显式写入，不等同于永久 forget。

### 引用链

1. 新推理段开始前，根据当前用户问题获取冻结 snapshot。
2. snapshot 只包含“关于我”和当前 ProjectId 可用的记忆，并经过有效性、纠正优先级、tombstone 和 promptware 过滤。
3. snapshot 以非权威历史上下文注入系统提示；模型必须服从当前用户指令。
4. 只有本次回答实际使用某条记忆时，回答末尾才生成轻量来源元数据。
5. UI 将来源元数据渲染为可展开入口，不把内部标签正文展示给用户。

### 跨会话链

1. 会话 A 成功写入后正常结束进程。
2. 会话 B 使用同一 `NOFY_HOME` 和同一 ProjectId 启动。
3. composition root 重新打开唯一 active store，并恢复 generation、manifest 和派生索引。
4. 会话 B 的第一次相关推理可以使用该记忆；不相关问题不应出现引用。

## 测试架构

在现有 `nofy-test-support` 和 built-binary E2E 基础上新增记忆场景，复用：

- `NOFY_BINARY`/本地构建产物解析；
- 隔离的 `NOFY_HOME`、HOME、临时工作区和 Git 仓库；
- mock inference server；
- ACP client 或 headless runner；
- 请求体、工具调用和最终输出观察能力。

mock server 使用预编排响应：第一次推理要求调用 `memory_write`，工具结果返回后生成正文；下一次或重启后的推理根据注入的 snapshot 返回固定回答和引用元数据。测试不得依赖真实模型判断是否“应该记住”。

旧 `tests/memory_integration/run_tests.py` 不再作为验收证据。实现阶段应删除它，或将仍有独立价值的场景迁移后再删除；不保留两套 E2E 入口。

## 最小 E2E 验收矩阵

### E1 显式写入与下一次推理

- 启动真实二进制和会话 A。
- 用户明确要求记住个人偏好。
- mock 模型调用真实 `memory_write`。
- 断言成功回执位于回答正文之后，范围为“关于我”，且提供撤销。
- 下一次推理请求包含该事实；成功回执之前不得提前声称已写入。

### E2 跨进程召回与安静引用

- 关闭会话 A 和进程，保留隔离的 `NOFY_HOME`。
- 启动进程和会话 B，提出相关问题。
- 断言推理请求包含已保存事实，回答末尾出现轻量“基于记忆”入口。
- 再提出不相关问题，断言不出现记忆引用入口。

### E3 项目隔离与 worktree 共享

- 项目 A 写入 Project 记忆。
- 不同 ProjectId 的项目 B 不能搜索、注入或引用该事实。
- 项目 A 的另一个 worktree 解析为相同 ProjectId，并能使用 ProjectWide 事实。

### E4 纠正优先级

- 先保存旧事实，再通过真实工具链纠正。
- 下一次推理与重启后的推理只包含新事实。
- 引用详情提供纠正后的事实，不泄漏已被 supersede 的旧事实。

### E5 永久忘记

- 写入事实，发起 forget 并完成确认。
- 断言成功文案只在 tombstone 与清理提交完成后出现。
- 重启、删除派生索引并触发重建、运行整理后，该事实仍不可搜索、注入或引用。

### E6 自动学习与子代理边界

- 顶层成功回合在持久化屏障之后产生 capture job，答案先于后台工作展示。
- 自动学习关闭时不产生 capture job，但显式写入仍成功。
- 子代理请求中没有 memory search/get/write/dream 工具，子代理回合不能独立提交捕获。

### E7 失败与安全体验

- 注入写盘失败，断言没有“已记住”成功文案。
- 敏感内容要求确认；secret 被拒绝且不进入模型后续 snapshot。
- promptware 内容被替换为阻断标记，不在回答或引用详情中回显原文。

## 分层执行与门禁

快速门禁运行不依赖真实账户的 E1、E2、E3、E4、E6 和 E7。E5 的索引重建可以进入较慢的 release E2E。所有场景使用确定性 mock server；任何跳过都必须使 release gate 失败，不能把缺少记忆文件、session-end race 或未触发工具调用记为成功。

建议命令形状：

```bash
cargo test -p nofy-shell --test memory_product_e2e -- --ignored --nocapture
```

测试保持 `#[ignore]`，因为需要预构建真实二进制；CI/release job 必须显式运行 ignored suite 并传入 `NOFY_BINARY`。同时保留以下内层门禁：

```bash
cargo test -p nofy-memory --no-fail-fast
cargo test -p nofy-shell memory
scripts/check-unified-memory.sh
```

## 错误处理原则

- 写入结果不确定时显示“尚未确认写入”，绝不乐观成功。
- 召回失败时继续回答，但不显示虚假引用；需要用户行动的持久失败才提示。
- ProjectId 无法确认时，项目记忆 fail closed；个人记忆是否可用按独立状态判断。
- 测试必须区分未提交、已提交但 acknowledgement 丢失、索引失败和模型失败。
- 所有临时目录、子进程和 mock server 在测试失败时也必须回收。

## 非目标

- 不实现知识库 provider。
- 不新增记忆版本选择器、dual read/write 或第二个 store。
- 不把自动学习活动做成逐回合通知流。
- 不要求模型自行判断引用来源；来源元数据由受信任的记忆服务和会话层产生。
- 本阶段不修改桌面端现有未提交工作；产品契约先在 Rust 二进制/ACP 边界闭环。

## 完成定义

- 当前 `nofy` 二进制拥有唯一、可重复运行的记忆产品 E2E suite。
- 显式写入成功回执只在持久化成功后出现，并位于回答末尾。
- 记忆实际影响回答时才显示轻量引用；不相关回答保持安静。
- 跨进程召回、项目隔离、worktree 共享、纠正、忘记、自动学习门控和子代理隔离均有外部边界证据。
- 旧 Grok Python suite 已迁移或删除，不再造成“文件存在即已覆盖”的假象。
- 全量 Rust 检查、记忆内层测试、built-binary E2E 和统一记忆守卫全部通过。
