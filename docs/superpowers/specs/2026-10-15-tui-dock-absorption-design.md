# TUI 底部 Dock 吸收设计

状态：待用户审阅；尚未实现。日期：2026-10-15。

## 目标与基线

将公开上游已有的统一底部 Dock 吸收到 Nofy fullscreen TUI，使工作流、子代理、后台命令、监控/循环和待发送队列在输入框上方集中呈现，并支持查看、停止、折叠与导航。

源码基线固定为 `upstream/main` 的 `2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8`（1.0.45）。这是可复核的移植基线，不代表后续产品发行版的全部界面。移植时保留原文件适用的许可证与归属。

## 方案选择

1. **采用：移植 Dock 展示/布局和交互，适配 Nofy 状态。** 沿用上游成熟布局规则，复用本地生命周期与操作分发；适配成本可控。
2. 仅把旧 TasksPane 移到底部。改动少，但无法补齐统一队列、分组配额和命中测试，不能满足此次吸收目标。
3. 整包覆盖 pager。接近上游但容易覆盖 Nofy catalog、提示区和模式快捷键等自有能力，不采用。

## 展示与用户操作

- fullscreen 默认使用 Dock，不依赖上游远程 `dock_enabled` 开关，不新增云端请求、遥测或账号要求。
- 分组顺序沿用上游：Workflows、Subagents、Tasks、Watchers、Queued。空组不占位；工作流子代理不得在独立子代理组重复展示。
- Dock 位于输入区上方的底部控制带，不再在顶部重复绘制旧任务面板；排队提示只绘制一次。Todo、catalog、侧问、插件提示和后续建议保留原有语义。
- 常态高度沿用上游 8 行预算；展开更多时受当前终端可用高度约束。空间不足时优先保留输入框，不能发生矩形越界或光标/鼠标错位。
- 支持分组展开/折叠、显示更多、组内滚动、键盘选择、鼠标点击与滚轮。光标、绘制和点击使用同一份布局结果。
- Enter 打开可查看条目；停止操作只针对当前选中的稳定 ID，沿用现有命令/子代理/监控/循环/工作流的停止分发。不可停止、已结束或已消失条目不得误杀其他任务。
- fullscreen 的 Ctrl+G 切换 Dock 显隐，隐藏状态保持到再次主动切换；隐藏后焦点返回有效面板。现有任务面板入口统一指向 Dock，避免两个并行任务界面。
- minimal 模式维持原行为：Ctrl+G 编辑外部提示词，`/tasks` 输出只读快照，不强行插入 fullscreen Dock。
- 子代理全屏查看器、其他接管屏幕的覆盖层出现时不绘制穿透 Dock；退出后恢复有效焦点和布局。

## 模块边界与接入点

- 新增 `crates/codegen/nofy-pager/src/views/dock/mod.rs` 与 `layout.rs`：适配上游纯展示与行预算，移除远程启用机制。模块不持有任务执行器或另建任务数据库。
- `app/agent_view`：从现有 `session.bg_tasks`、`subagent_sessions`、`scheduled_tasks`、`workflow_runs`、`pending_prompts` 构建 Dock 快照；记录稳定条目标识，事件处理时复核目标仍存在。
- `views/agent.rs`、`app/agent_view/render.rs`：增加底部 Dock 布局区域与渲染，关闭重复旧任务/队列区域，保留 Nofy 自有布局参数。
- `app/agent_view/panes.rs`、`input.rs`、`app/mouse.rs` 与实际焦点路由：接入导航、显隐、查看及停止；共享既有操作通路，不另建后台调度体系。
- `actions/defaults.rs` 及帮助/提示文本：反映 fullscreen 新含义，同时保留 minimal 模式按键归属。
- `views/tasks_pane.rs`：实施时审计调用关系；保留仍被使用的状态转换和操作能力，仅在确认无调用且验证通过后删除被替代的展示代码。

## 状态变化与异常

- 完成、删除、重排或会话切换后，选择优先跟随同一条目 ID；条目消失则收敛到有效行，空 Dock 退出焦点。
- 已请求停止的条目显示现有 pending 状态，不因重绘反复发送停止请求；失败反馈沿用现有通路。
- 渲染不执行阻塞 I/O、不创建独立轮询循环。计时与刷新复用既有事件循环。
- 不为 Dock 改变任务的存储、恢复、通知或调度语义。

## 验收与测试

1. 移植并适配上游 Dock/layout 单测，覆盖空数据、五组混合、折叠、显示更多、高度收缩与 Unicode 截断。
2. 补 Nofy 集成回归：键盘/鼠标命中一致、焦点切换、Ctrl+G 两种模式、队列不重复、查看器接管、任务动态消失和稳定 ID 停止。
3. 用现有测试夹具驱动后台命令、子代理、监控/循环、工作流和排队状态；断言操作实际到达原分发通路，不能只断言出现文字。
4. 运行 pager 相关测试与实际二进制构建；编译采用无增量、无 debug 信息配置，控制 target 体积。
5. PTY 验证真实交互：启动、任务出现、焦点导航、展开、查看/停止、终端缩放、任务结束/消失、会话切换。无模型凭据时使用本地夹具，并明确未覆盖的真实服务场景。
6. 每次修改现有符号前执行 GitNexus impact，报告调用影响；提交前运行 detect_changes 并核对本批范围。不得把既有脏工作区变更混入本批提交。
7. 完成后更新上游吸收台账：记录基线、已吸收项目、验证命令及未覆盖项，不宣称整个 TUI 已与最新产品发行版对齐。

## 非目标

本批不实现未公开发行版的 `/density` 等新功能，不扩展 `/workflow` 命令集，不改桌面端、记忆体系、版本机制、模型目录或后台任务内核。后续 TUI 差异另行审计；本设计不将它们标记为已吸收。
