# Nofy 统一记忆体验契约

本文定义统一记忆系统必须向用户提供的稳定行为。实现可以调整内部文件、数据库和模型调用，但不得改变这里的用户心智模型、即时生效语义和隐私承诺。

## 用户心智模型

用户只接触一个“记忆”功能和两个区域：

- **关于我**：跨项目生效的稳定偏好和个人事实。
- **当前项目**：只在当前项目生效的项目事实、约定和决策。

用户只需掌握四个动作：

- **记住**：保存一条明确的信息。
- **纠正**：用新事实取代旧事实。
- **忘记**：不可撤销地清除指定信息。
- **解释**：说明记住了什么、来自哪里、在哪个范围生效。

普通界面不得要求用户理解 scope、observation、topic、rollout、lease、revision、hash 或 operation ID。这些术语只能出现在技术详情、日志和架构文档中。

## 主助手与项目边界

- 主助手是唯一的记忆协调者，可以读取“关于我”和“当前项目”。
- 子代理只接收主助手筛选的任务相关只读片段，不能直接查询、写入、纠正、忘记或整理记忆。
- 子代理输出只有被主助手验收并写入成功的顶层回合后，才可能成为自动学习候选。
- 同一 Git repository 的主 checkout 和 worktree 共享一个稳定项目身份。
- 分支特有事实只在匹配的 branch/commit 上生效；项目通用事实可在同项目的不同分支使用。
- 当前用户明确指令高于当前项目明确规则；项目明确规则高于“关于我”的默认偏好；显式事实高于自动学习结果。

## 用户设置

普通设置只提供：

- 记忆总开关。
- 自动学习开关。
- 允许写入“关于我”和“当前项目”的范围控制。
- 自动学习敏感类别排除：凭据、财务、健康、身份和位置。

关闭记忆后不注入记忆，也不自动学习。关闭自动学习后，用户仍可显式执行记住、纠正和忘记。内部 RecordOnly、Shadow、Active 等发布状态不能绕过用户设置，也不得显示在普通界面。

## 场景 1：立即记住

**Given**

- 记忆已开启。
- 用户位于项目 A。
- 当前没有“默认使用 Rust”的记忆。

**When**

- 用户说：“记住我默认使用 Rust。”

**Then**

- 主助手将信息保存到“关于我”。
- 写入、索引和当前会话 snapshot 更新全部成功后才显示成功。
- 下一次模型推理可以使用该信息。
- 项目 B 中也可以使用该个人偏好，但项目 B 的明确语言约束优先。
- receipt 提供短期撤销动作；撤销只适用于本次记住。

**用户可见文案**

> 已记住到“关于我”：默认使用 Rust。撤销

如果用户明确说“这个项目默认使用 Rust”，则保存到“当前项目”：

> 已记住到“当前项目”：默认使用 Rust。撤销

## 场景 2：立即纠正

**Given**

- “关于我”中存在“住在北京”。
- 当前 session snapshot 已包含该事实。

**When**

- 用户说：“其实我现在住在上海。”

**Then**

- 主助手创建显式纠正并关联被取代的旧事实。
- 旧事实立即退出默认搜索和注入结果。
- 当前 session snapshot 在下一次模型推理前更新。
- 旧事实只作为不可直接召回的审计证据保留。
- 自动学习结果不得覆盖该纠正。

**用户可见文案**

> 已更新“关于我”：现居上海。旧的“住在北京”已停止使用。撤销

## 场景 3：彻底忘记

**Given**

- 活动记忆、索引、当前 snapshot 或短期迁移灾备中存在用户公司名称。

**When**

- 用户说：“忘掉我的公司名称。”
- 主助手展示清除范围，用户确认。

**Then**

- 先提交不包含正文的 tombstone，使内容立即不可召回。
- 删除迁移灾备密钥和灾备包。
- 删除或改写规范文件并更新所有索引和清单。
- 使所有活动 session snapshot 中对应内容失效。
- 任何步骤失败都不得显示成功；系统显示“尚未完全忘记”并继续可恢复的清理操作。
- 完成后重启、重建索引或执行自动整理都不能恢复该内容。
- 忘记不可撤销。

**确认文案**

> 将从“关于我”、当前会话和可恢复灾备中永久删除“公司名称”。此操作无法撤销。继续？

**成功文案**

> 已永久忘记“公司名称”。

**未完成文案**

> 尚未完全忘记：清理仍在继续。在完成前，这条信息不会用于回答。

## 场景 4：解释来源

**Given**

- 主助手准备使用一条个人或项目记忆。

**When**

- 用户问：“你为什么知道？”或打开记忆详情。

**Then**

- 显示事实摘要、作用范围、来源类型、来源对话或显式操作时间。
- 提供“纠正”和“忘记”动作。
- 默认不显示文件系统路径、数据库键、hash 或 operation ID。
- 技术详情可以显示脱敏后的 revision、hash 和 operation ID。

**用户可见文案**

> 我在 2026-09-20 的对话中记住了这条信息，范围是“当前项目”。你可以纠正或忘记它。

## 场景 5：项目隔离

**Given**

- 项目 A 记住“部署目标是 Cloud A”。
- 项目 B 没有该事实。
- 两个项目可能拥有相同目录名，但 ProjectId 不同。

**When**

- 用户在项目 B 开始新会话。

**Then**

- 项目 A 的事实不出现在项目 B 的 snapshot、搜索或自动整理输入中。
- “关于我”的稳定偏好仍可使用。
- 同一项目 A 的另一个 worktree 共享 ProjectId，可以使用 ProjectWide 事实。
- 项目 A 的 BranchLocal 事实只在匹配的 ref/commit 上使用。

**泄漏错误文案**

项目隔离失败属于安全错误，不降级为警告，也不向模型注入可疑内容：

> 项目记忆暂时不可用：无法确认当前项目身份。

## 场景 6：关闭自动学习

**Given**

- 记忆总开关已开启。
- 自动学习已关闭。

**When**

- 用户完成普通顶层对话。

**Then**

- 不创建自动 capture job，不调用提取模型，不执行自动整理。
- 已有记忆仍可用于回答。
- 用户仍可显式执行记住、纠正和忘记。
- 内部 rollout 状态不能重新启用自动学习。

**显式记住文案**

> 自动学习已关闭，但我已按你的明确要求记住到“当前项目”：……

## 后台行为

- 答案先展示，自动 capture enqueue 不得位于生成答案的关键路径。
- 正常 capture 和 consolidation 保持静默，不逐轮通知。
- 只有持续失败、迁移完成或需要用户决定时才通知。
- 显式记住、纠正和忘记必须在返回成功前完成用户可感知的一致性更新。

## 敏感内容

- 凭据和可识别 secret 永不持久化，即使用户显式要求也拒绝。
- 自动学习命中用户排除的财务、健康、身份或位置类别时，不将正文发送给提取模型或写入 quarantine、telemetry、索引和重试队列。
- 用户显式要求保存被自动排除的非凭据敏感类别时，先说明保存范围和风险并请求确认。

## 未来知识库边界

知识库不属于本期记忆功能。本期只定义独立、只读的 `KnowledgeBaseProvider` trait 及其 search/get 数据契约：

- 不注册目录。
- 不扫描或索引外部文件。
- 不将知识文档写为 Observation 或 Topic。
- 不把 provider 注入 MemoryService、Shell、agent builder 或 Pager。
- 不展示知识库设置、空状态、灰置入口或用户命令。
- 旧 `roots.json` 只记录到迁移报告的 `deferred_knowledge_sources`，运行时不读取。

后续知识库项目必须通过 composition root 接入，并单独定义权限、来源可信度、注入预算和 promptware 防护。

## 实现术语附录

- **Scope**：Personal 或 Project 的内部标识。
- **Observation**：不可变的来源事实或显式操作记录。
- **Topic**：由证据支持、可按 revision 修订的记忆投影。
- **Snapshot**：一次模型推理可见的冻结记忆集合。
- **Rollout**：自动捕获和整理的内部发布状态。
- **Lease**：后台 worker 的限时执行所有权。
- **Hash**：并发控制与一致性验证值。
- **Operation ID**：可恢复操作的内部追踪标识。
