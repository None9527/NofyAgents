- 规范 Markdown 与 SQLite 实际复制到独立物理 generation，保留多 Project、Personal、ID、时间、Undo、Tombstone 及已结束捕获历史。原目录保持，目标索引按新维度重建；未完成捕获、原生操作、撤销或运行效果阻止迁移。
- 管理 API 经过原发布资源选择器计划和准备，按原 command_id/fingerprint 提交、撤销准备或恢复。准备期间两端拒绝接纳；提交同事务退休源并激活目标。旧声明不能通过本地 reopen 绕过退休，排队任务和真实执行有命名空间边界。
- 反向迁移另建物理副本，包含目标侧后来写入的数据；旧命令只重放原回执。保留的旧编译连接会因 storage_generation 改变而刷新，旧 Undo token 可用，已忘记内容不复活。
- 默认 Host 实际 Agent 停驻后迁移、切换 tool_catalog/context_sources，并覆盖反向数据迁移与原模块回退。会话状态摘要和原预算保持，已成功 HTTP 工具效果始终一次，继续后使用正确活跃存储。
- 实际进程在意图、准备及发布边界退出后，原命令可恢复；默认 CLI 准备后 SIGKILL、重启仅凭命令身份提交，再次硬退出后可读取/重放完成回执。已关闭根的历史读取不探测退休存储。元数据行丢失不重新打开原始目录。
- 依赖提取只遍历编译后的模块定义及明确 Workflow 文档；工具参数中相似的 factory/config JSON 仍是普通载荷。合法 Workflow 省略可选 modules 时按原 Schema 取空列表。

## 实际失败与修复

1. 首次 Memory 库225通过、2失败：SQLite 只读打开仍可能创建空 WAL，原指纹将其误认作数据改变。仅排除没有提交内容的零字节 WAL，非空 WAL 和实际数据库/规范文件继续校验；完整 Memory 补验通过。
2. Host 验收夹具混用了 SSE 事件类型，修正为原显式转换；Host 库76通过、2失败指向撤销事务使用了只读连接，改为完成所有权核对后打开可写目录库提交。迁移专项6项通过。
3. 公共接纳检查误将合法空 Workflow 缺少 modules 当作损坏，按原可选字段默认修正。另两份新 HTTP 夹具改用原 command_id 与 input_schema 契约。
4. 首次 HTTP 观察进程以143退出，未形成整批收尾，原因未确立。保留同一编译二进制逐项169通过、9失败和10未确认的记录；集中补验这19项全部通过。没有将观察中断当作产品成功或宣称首波全绿。
5. 并行依赖边界检查先于 Cargo 依赖边写回，初次 --locked 拒绝；离线解析后补验通过。Cargo.lock 仅增加 Host 对三个已有依赖的引用，没有外部版本更新。
6. 首次控制台审查发现长回执不可键盘滚动和资源组 ARIA 角色缺失；仅修正对应视图。修复后实际键盘 PageDown 滚动270px，axe违规0、未判定0。QA 包装器重开浏览器时先使用了已停止的本机地址，等待新宿主就绪后改用新地址；这条操作记录保留，不算产品缺陷。

所有原始日志与阶段失败在 /tmp/nofy-memory-transfer.k5a1ge7c 保留，结构化索引为同目录 failures.json、wave.json、repair-wave.json、repair-2-wave.json、repair-3-wave.json 及 http-first-observations.json/http-accepted.json。

7. 归档静态复核发现以 `@root/` 开头的相对历史路径会与绝对路径归一化标记混淆。修复为仅映射绝对路径，新增实际 SQLite 回归；迁移组17项（Memory6、Host库6、HTTP5）和受影响编译/文档/格式检查全部通过。最终Memory去重334、总计605；其余已通过用例不重复。

## 控制台与边界
