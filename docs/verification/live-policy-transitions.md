# L3b3：运行中普通权限策略更新验收

同一进行中根 Agent 可通过原 `update_modules` 命令显式更新普通 `policies` 集合，不重编译或重启宿主。新策略作用于后续根工具派发，强制权限、历史、原执行身份、审批事实和预算账本保留。完整权限及其他有状态模块迁移仍未完成。

## 实现边界

- `ModuleUpdate.policy_set` 显式选择；`LiveModuleState.policy_set` 累积记录并进入会话种子。未选择时仍拒绝改策略。
- `Agent::with_live_modules` 只替换普通策略句柄及 spec 标识，继续使用原 `PolicyFloor`、组合和持久命名空间。Hook 和子调用按各自声明及继承的强制权限执行，不把根普通策略集合宣称为所有调用的统一配置。
- 所有强制策略及其传递依赖、预算、绑定、上下文、动态工具来源，以及未选择的其他能力保持原身份；共享依赖不能借策略选择被改写。
- 使用过新选择的有效版本为 `nofy.live/v3`；后续仅更新模型/Prompt或回滚策略仍保留该迁移事实。新增 false 字段省略序列化，受支持 v1/v2 历史命令及状态编码不变。
- 持久引用扫描器识别 v3，并保留目标快照和 before/after 组合遍历；未知协议仍拒绝。没有新增执行循环、宿主或依赖。

生产代码只改 Runtime 的五处：`agent.rs`、`supervisor/jobs/managed/actions.rs`、`transition.rs`、`transition/compatibility.rs`、`durable/retention/decode.rs`。另修改两处测试注册，新增两份测试文件。契约、拓扑和管理命令见[权限更新契约](../architecture/live-policy-transitions.md)。

## 风险与实际失败

编辑前 upstream 分析为 CRITICAL：`validate_seed` 影响 28 符号、13 流程、5 模块，涉及恢复、版本读取及会话交接。`with_live_modules`、命令摘要、有效版本和 Worker 路径也已集中分析。图谱的 Rust 字段、派生及模块别名边不完整，实际调用与行为验证共同限定范围。

首轮新增 Runtime 六项通过，4.779 秒；默认 Host 新专项失败，22.676 秒。实际日志为 `unsupported retained live protocol`，新权限管理回执未完成，有效版本仍是之前的 v2，没有提交新版本。原因是 Host 的资源提交围栏会扫描持久引用，而该扫描器只识别 v1/v2；直接使用 Runtime 的测试不装载这条 Host 围栏，因此不能替代宿主验收。

补充分析 `inspect_retained_modules` 为 HIGH，5 个直接调用方、2 流程、3 模块；报告后仅补充 v3 协议识别，不跳过引用扫描、不放宽未知版本处理。原失败及源码/制品冻结保存在 `attempt-1/`。修复后重新构建，原宿主专项以相同条件通过，37.316 秒。
