# CLEAN5d：管理宿主注册表共享与并发回执验收

2026-11-03。CLEAN5c 留下的管理动作回执超时已复现、定位并修复。只有两个生产源码文件改变私有注册表所有权；没有延长期限、修改业务断言或增加依赖。完整平台仍未交付，本报告只关闭本次复现的性能缺陷。

## 根因与修改

`KernelHost` 和 `ControlPlane` 派生 `Clone`，原先按值持有 `ModuleRegistry`。Axum 请求状态和后台控制任务克隆宿主时，会递归复制工厂描述及其 JSON Schema。并发轮询因此反复分配、复制和释放静态元数据，在测试的单线程异步执行器中阻碍模型及控制任务继续执行。

- `crates/common/nofy-agent-host/src/lib.rs`：完成启动期工厂注册后，以 `Arc<ModuleRegistry>` 保存只读注册表。
- `crates/common/nofy-agent-runtime/src/control/service.rs`：构造参数仍接受原有 `ModuleRegistry`，内部以 `Arc` 共享启动期元数据。

编译所需的声明覆盖表仍独立创建；本次共享不冻结可装载业务配置，也不使不同 generation 共用可变声明。公开构造接口、声明/快照序列化、数据库结构、事务围栏、审批、预算、执行隔离、15 秒回执期限和源码打包边界均未改动。

编辑前已做 upstream 分析。图谱对两个 Rust 类型的字段所有权及派生 `Clone` 边返回 LOW/0，不能据此判定没有影响；结合具体调用，按 HIGH 报告请求状态、后台任务及 prepare/rebind/publish/apply 范围，再限定两处修改。分析原文保存在 `impact-registry-sharing.json`。
