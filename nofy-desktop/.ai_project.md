# Nofy Desktop 项目上下文

## 开发入口

主线为本目录。`../ref-desktop` 是 ZCode 官方源码参照，`../desktop` 是旧壳，只阅读。
架构优化入口：[前端架构审查与迁移方案](docs/architecture/frontend-optimization-2026-10-09.md)。后续结构调整按 A0–A6 推进，A0 依赖门与 A1/A2/A3 第一批已落地；以 [最新架构收口](docs/architecture/frontend-closeout-2026-10-11.md) 的 A0–A6 状态、验收和剩余边界为当前事实。
原功能执行顺序见 [前端完善计划](docs/superpowers/plans/2026-10-08-frontend-completion.md)。
修改既有函数前执行 GitNexus upstream impact；提交前 detect_changes。

## 栈与边界

内核独立且拥有自己的 TUI；桌面是 ACP 客户端。renderer/core 仅为客户端投影与协议适配，application 仅协调客户端用例，不实现 agent loop。Codex 官方源码参照和边界约束见架构方案第 0 节。

Electron、React 19、TypeScript strict、Vite、ACP、reducer store、xterm。
main 拥有单个 `nofy agent stdio`；preload 提供 typed bridge；runtime.effect 是内核动作出口。
UI 以 16ms 合并 store 渲染通知，投影与实时 getState 不节流。
配置保存有独立 native bridge：检查任务/审批，停止并等待内核退出，受限 JSON patch，重新握手。

## 状态所有者

内核：会话、队列、审批、模型生效状态、MCP/插件配置。
窗口偏好：项目导航、草稿、主题/语言/字号、会话归档/置顶/未读/分组。
本地归档不删除内核历史，不代表云同步。密钥不进入窗口偏好或验收记录。
回退先 `force:false` 预览，复查无冲突后 `force:true` 提交，再 fresh load；不要把预览当完成。
transportEpoch 隔离重连后复用的请求 id；旧请求对象不可应答。

## 命令

从本目录执行 `pnpm dev`、`pnpm build`、`pnpm start`。
`pnpm verify`：生成契约、架构边界检查、共享样式检查、类型、单测、夹具审计、构建与三类 smoke；不包含 GUI。
GUI：`node apps/desktop/e2e/renderer-acceptance.mjs`、`project-actions.mjs`、`settings-acceptance.mjs`、`workspace-acceptance.mjs`。
GUI 使用精确锁定的 playwright-core devDependency，可由 PLAYWRIGHT_CORE_PATH 指定 ESM/CJS 驱动。
本机性能门：pnpm verify:performance，顺序三次采样，不与其他 GUI/构建并发。
真实线路：`node apps/desktop/scripts/probe-live-acceptance.ts`、`probe-turn-rewind.ts`；隔离测试可复制本机配置，禁止输出原始配置/协议帧。
发布候选：`pnpm package:mac`、`pnpm verify:package`。输出 release/mac-arm64；本地 ad-hoc 签名。

## 当前边界

真实网络测试模型为 gemini-3.8-flash-high。测试读取本机凭据，不把密钥放入源码。
模型 JSON writer 不迁移旧 TOML；外部 CLI 不共享 desktop lock，末次 CAS 到 rename 的并发窗口仍存在。
内核没有原子回退预览/提交 CAS；GUI 复查并阻止已知冲突，不宣称能阻止所有并发外部编辑。
Windows/Linux、Developer ID、notarization 与远端 CI 尚未作为本次实测通过项。
