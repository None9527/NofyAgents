# Codex 右侧工作区深度调研

日期：2026-10-09。对象：用户截图、本机 Codex 26.930.51102 build 13100 安装包、ZCode 3.14.3 源码、当前 Nofy Desktop。
状态：研究与目标设计，尚未实现右侧工作区迁移。

## 1. 结论

截图这一块应视为“围绕文件资源工作的工作区”，而不只是对话旁边的一块辅助面板。它把标签、文件身份、正文/源码、目录导航、外部打开与编辑生命周期放在同一条操作链里。

Codex 在这个布局中的优势是上下文连续：当前文件是主角，文件树是其邻接导航，切换内容形态不需要重新找到文件。ZCode 也具备标签去重、Markdown 预览/源码、文件树与监听；差异主要在默认组织方式，不能简单说 ZCode 没有这些能力。

Nofy 的主要差距是模型和承载：AuxTab 只有 files/review/agents 三个功能类别，FilePane 将一个文件预览放在树下方，尚不是多个资源标签的工作区。只修改 CSS 无法补齐这一点。

## 2. 证据等级与限制

- 界面观察：用户截图可确认标签栏、面包屑、源码切换按钮、文件树开关、外部打开按钮，以及正文与文件树并列。
- 静态确认：安装包可确认相关模块、导入关系、状态字段、命令与关闭/保存机制。
- 待实测：各交互的最终行为、键盘完整性、重启恢复、读写原子性、实际性能。

Computer Use 工具明确禁止自动操作 `com.openai.codex`；本轮未用别名、CDP 或其他方式绕过。没有对运行中的 Codex 做点击与性能追踪。源码地图缺失，因此没有恢复官方原始源码结构。
提取代码仅保留 `/tmp/nofy-codex-shell`，项目内只存研究和 [证据元数据](codex-right-workspace-evidence-2026-10-09.json)。

## 3. 截图中为什么更顺手

| 界面组织 | 用户收益 | 对 Nofy 的启示 |
|---|---|---|
| 标签栏表示具体资源，而非只有“文件”类别 | 文件 A/B 可以分别保留阅读位置 | 资源标签成为一级状态 |
| 标签栏下只出现当前文件的路径和动作 | 资源身份明确，操作对象明确 | Header 从选中资源派生，不重复保存路径 |
| 面包屑在正文上方 | 看文件时不用再去左边找目录归属 | 路径导航与文件阅读共用上下文 |
| 查看源代码是同文件的模式切换 | 阅读和检查源码之间的成本低 | 同一 Tab 内保存模式、位置与焦点 |
| 文件树在内容右边且可隐藏 | 可以找下一个文件而保留当前正文 | 目录成为工作区导航，不占据正文上方 |
| 外部打开是主动作加下拉选择 | 常用编辑器一步打开，其他应用仍可达 | 目标选择和执行分离，未安装应用不可假成功 |
| 正文、目录各自滚动，弱分割线 | 高信息密度下仍有稳定空间关系 | 独立滚动容器、正确 min-width/min-height |
| 空白与颜色克制，选中行和活跃标签清晰 | 视线落在文件内容而非装饰卡片 | 沿用共享主题，减少重复容器和描边 |

截图为裁切/缩放图，不从像素直接推断 CSS 字号与最终尺寸。文件树行名被长路径截断时仍须有完整路径提示；窄工作区不能强行保留并排树。

## 4. 静态实现揭示的职责

### 4.1 资源打开与标签身份

`open-text-file-editor-side-panel-tab.electron` 对外提供统一打开入口，实现位于公共应用包；静态调用包含 hostId、path、workspaceRoot、line/column、target、isPreview、replaceTabId。
默认文本编辑标签身份由宿主与文件路径组成；会先查文件是否已在 right/bottom 面板，并选择已有位置。不能据此推断同一路径在所有会话或窗口都共享同一实例。

打开调用包含 durableRoute、payloadVersion、默认 tab state 和关闭/撤销关闭回调。说明它设计了可序列化恢复入口；完整重启恢复未在本轮实测。

文件树的选择回调走 isPreview:true，明确打开回调走 isPreview:false；组件同时有 onSelectionChange/onDoubleClick。可确认临时预览与正式打开分开，不把“选择一个文件”简单等同于永久多开一个标签。

### 4.2 标签状态与文件正文分离

tab state 包含 markdownMode、源码滚动位置、文本/编辑器草稿、行定位和滚动状态。标签身份、文件数据、视图状态具有不同生命期。

文件编辑组件接受 tabId/tabState/setTabState 与 hostId/path；目录组件报告 expandedPaths、scrollTop、selectedPath。标签切换无需把整个树和阅读状态重新当作默认页面初始化。

### 4.3 正文/源码不只是换一个组件

`text-file-editor-tab-content.electron` 有 Markdown/source 模式协调器，切换前检查 activeSave 和未保存状态，且检查异步保存期间模式/保存入口是否已变化。失败不会直接完成切换。
源码编辑器存在只读控制、查找、跳转行、撤销/重做、草稿和关闭处理。图中的 Markdown 视图背后也有编辑与保存状态，不能按“静态 Markdown + 一个开关”完整复刻。

Nofy 第一阶段可只读：先统一资源身份与阅读模式。写入/编辑需另行落实保存契约后开放，不因按钮外观齐全就冒充可编辑。

### 4.4 文件树的数据与视图分开

`workspace-directory-entries-query` 按 hostId、workspaceRoot、directoryPath、includeHidden 等身份查询。根目录与 expandedPaths 对应目录分别读取并汇总可见路径，使用 queryKey、AbortSignal、placeholderData 与 FIVE_SECONDS 过期策略。

`base-file-tree` 承载选中、展开、滚动恢复、粘性目录、文件图标/Git 装饰和右键菜单；独立于正文读取。实际树由独立模型/渲染接口组织，不是页面内任意递归 JSX 的全部逻辑。
截图中包含隐藏目录；静态查询也明确传 includeHidden。是否显示隐藏文件应是显式偏好，不能与“是否遍历 .git 的巨大内部目录”混为一谈。

### 4.5 文件树是正文内的可折叠布局

`review-file-tree-side-pane` 有边缘拖动控件、宽度/最大宽度约束、显隐与动画；编辑 Header 有文件树开关。路径面包屑还支持目录项查询与预览打开。

存在两个布局层：外层 right/bottom 工作面板，内层正文旁的文件树。外层面板宽度与内层树宽度不能使用同一个变量，否则会相互影响。

### 4.6 外部文件修改和关闭保护

编辑产物有 baseMtimeMs、expectedMtimeMs、磁盘读取/外部同步版本、待处理外部变更与冲突读模型。
干净文件可以重读外部修改；未保存草稿需要审查/冲突处理，不能无条件覆盖。保存带版本前提，但本轮没有证明服务端的所有写入原子性。

onBeforeClose、saveUntilClean、保存错误与放弃确认构成关闭协议；dispose 会处理草稿、滚动快照、定时器、AbortController 和 editor 实例。
这是值得学习的可靠性部分，不能只模仿标签样式。

### 4.7 文件操作与会话关联

文件树/工具栏支持外部打开目标、复制路径、另存和添加到对话；静态实现携带 host、workspace、conversation 等上下文。
选中文本与文件路径添加到对话属于客户端产品用例；智能体执行和权限仍归内核。面板关闭不是取消内核会话。

## 5. 与 ZCode、Nofy 的准确对照

| 能力 | Codex 证据 | ZCode 源码 | Nofy 当前 |
|---|---|---|---|
| 文件资源标签复用 | 稳定文件身份与已有面板定位 | workspaceSidePane 按 sourceKey + owner 复用 | AuxTab 为功能类别，一个 FilePane 内只有一个 preview |
| Markdown/源码切换 | 模式协调与编辑生命周期 | PreviewPane 的 preview/code 模式 | 文件主要通过 CodeBlock 显示 |
| 当前文件与目录联动 | 内嵌文件树、选中路径、目录面包屑 | WorkspaceSidebar 内树；activePreviewPath 联动右侧 PreviewPane | 树与预览上下堆叠 |
| 目录加载/刷新 | 目录查询身份、展开目录汇总、取消信号 | 独立 data/watch/search/virtual list hooks | 逐层 fs/list，目录局部状态 |
| 阅读状态保存 | 每 Tab 的模式、滚动、草稿字段 | 标签状态/预览已有保存与重内容延迟处理 | FilePane 挂载局部状态，切换功能标签会失去视图状态 |
| 保存与冲突 | 版本前提、外部变更、关闭保护 | 本次 PreviewPane 是预览承载；不据此断言整个产品无编辑能力 | 尚无文件编辑事务 |
| 多类型扩展 | 文件/审查/产物等独立入口和 Frame | 多种 SidePaneTab，状态模块较大 | files/review/agents 三类别 |

ZCode 的 relevant 文件：`PreviewPane.tsx` 1806 行；`workspace-file-tree/WorkspaceFileTree.tsx` 803 行；`lib/workspaceSidePane.ts` 包含多类型标签状态与复用规则。它已有很多能力，集中编排和默认布局仍可优化。

## 6. Nofy 的源码风险与模型缺口

- **P1，待运行复现**：FilePane.openFile 的异步结果没有选择代际校验。快速打开 A/B 时，A 的迟到响应可能把 B 的预览覆盖；换根目录后旧目录请求也可能回写。应在资源查询层解决，不为每个按钮复制一个 ref。
- **P2**：files/review/agents 是功能枚举，无法表达多个具体文件标签、同文件去重和预览槽位。
- **P2**：FilePane 直接订阅整份 runtime.store；文件浏览仍可能受无关会话流通知影响。
- **P2**：阅读模式、树状态、tab identity 与数据请求混在页面局部状态，难以恢复和复用。
- **P2**：读取 maxLines=4000、目录 limit=500；新布局必须清楚展示截断，不能把截断内容当完整文件或完整目录。

本轮没有修改这些函数；实现前继续按项目要求运行 GitNexus upstream impact。

## 7. 建议目标：一个有明确边界的 WorkspacePanel

```text
WorkspacePanel（外层布局与标签栏）
  ├─ PanelTabRegistry（类型、入口、能力、恢复与关闭协议）
  ├─ ResourceTabs（资源身份、预览槽、正式标签、激活）
  └─ FileWorkspace（文件工作区）
       ├─ ResourceHeader（路径、模式、树开关、外部打开）
       └─ SplitContent
            ├─ ViewerHost（Markdown / Code / Image）
            └─ WorkspaceExplorer（树、筛选、选中、路径定位）
```

这属于已有架构计划的 workspace 领域，不建立另一个 Runtime，也不向 panel 注册表加入任意协议调用。

### 状态契约

| 状态 | 唯一所有者 | 身份/生命周期 |
|---|---|---|
| 文件身份 | application/workspace 资源模型 | local host + workspace identity + 规范化路径；不盲目全路径转小写 |
| 标签顺序、激活与预览槽 | application/workspace panel store | 窗口/工作区作用域；核实会话切换策略 |
| 文件字节、版本与加载错误 | 文件查询层 | 资源 key + 请求代际；迟到响应不能改变当前选择 |
| 目录列表与刷新 | explorer 查询层 | 根目录/子目录/隐藏偏好；按展开加载 |
| 阅读模式与滚动 | 每个资源 Tab 的视图状态 | 资源复用时保留，不重置整个工作区 |
| 树展开、选中、筛选 | 工作区 explorer 状态 | 隐藏树保留；换根隔离 |
| 本地编辑草稿与 dirty | 未来 editor controller | 未实施前只读；保存/冲突/关闭单独验收 |
| 面板宽度、树宽度 | 共享布局偏好 | 两个独立尺寸，最小正文空间优先 |

注册表只描述类型、视图工厂、能力、序列化与关闭协议；用例由 application 门面执行。正文 Renderer 不取得整个 Runtime，树不负责管理内核会话。

### 建议交互规则

1. 文件选择使用一个临时预览槽；明确打开保留正式资源标签。已有同资源标签优先激活，不重复开。
2. 预览/源码在同 Tab 切换，保留各自位置；切换文件时资源标题、内容、树选中状态保持一致。
3. 目录筛选可以换结果列表，但当前文件正文保持；点目录只展开，不把目录误当可读文本。
4. 同名文件用路径/父目录区分；长路径可水平浏览或折叠，不挤掉主动作。
5. 隐藏树不销毁文件；关闭 Tab 释放它的视图资源，但保留目录查询缓存的受控生命周期。
6. 窄窗口先收起树，必要时使用可关闭的目录抽屉，不牺牲正文宽度或制造多重横向滚动。
7. 外部打开/在文件管理器显示作为 typed 宿主能力；失败可见。现有 NofyBridge 没有完整这组能力，先设计接口再实现。
8. 未来编辑开启后，临时预览替换、Tab 关闭、工作区切换都必须经过同一 dirty-close 协议。

## 8. 接入现有 A0–A6 的实施顺序

| 原阶段 | 本领域切片 | 退出标准 |
|---|---|---|
| A0 | 记录现有 FilePane 操作/异步竞态与布局基线；盘点 fs 与宿主能力 | A/B 迟到响应、换根、截断等场景可复跑 |
| A1 | 文件/目录读取窄接口、资源身份、请求代际；宿主外部打开能力契约 | 页面无线路字段；跨根/跨会话结果不污染 |
| A2 | ResourceTabs 与 PanelTabRegistry，迁出 App 面板状态 | 同文件去重、临时/正式标签、关闭回退与状态恢复 |
| A4 | 正文主视图 + 右侧可折叠树 + 统一 Header；Markdown/源码只读切换 | 深浅主题、窄窗口、键盘与长路径验收 |
| A5 | 大文件/目录性能与受控缓存、滚动定位 | 数据/DOM 数量受控，展开和阅读位置稳定 |
| 后续能力切片 | 有写入契约后添加编辑、保存与外部变更冲突 | 版本冲突不覆盖，关闭失败保留草稿 |

不通过直接改内核或让前端自行调用模型完成右侧工作区。当前 ACP 的 fs/list/readFile 可继续作为读取来源；写入与 watch 缺口单独登记，不能由 UI 伪造能力。

## 9. 验收清单

- A/B 连续选择且响应乱序：最终只显示 B 的标题、正文与选中行。
- 同路径多次打开：不新增重复资源标签；不同工作区/同名文件不串数据。
- 临时预览替换与正式打开：状态规则一致；正式标签阅读位置保持。
- 源码/预览切换、隐藏树、关闭非激活标签：当前正文和焦点合理保留。
- 无根、空目录、读取失败、文件被删除、搜索无结果、权限拒绝：均有真实状态。
- 目录/文件截断、二进制与大文件：不假装完整可编辑。
- 中文/空格路径、隐藏文件、大小写敏感路径：资源身份正确。
- 1024 窗口和深浅主题：Header 可操作，目录可收起，正文可读。
- 未来编辑：外部修改、版本冲突、保存失败、关闭失败不丢草稿。
