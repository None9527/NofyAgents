# 设置路由、查询与退出模块

2026-10-10。在已交付的 MCP/插件写入服务上，整体迁移分区呈现、清单查询和表单退出。内核及协议不变，无新依赖，无新增架构豁免。

## 模块边界

sectionRegistry.tsx 注册通用、模型、插件、技能、MCP、用量六个渲染器及图标。SettingsSurface 保留路由框架、资源读模型和分区刷新，不再展开六组页面 JSX；SettingsBoundary 提供统一退出上下文。

application/settings/resourceCache.ts 持有不可变查询快照、读请求去重、30 秒缓存有效期与请求代际。resources.ts 集中模型配置、认证信息、插件、市场、技能、MCP、bundled catalog、hooks 八类资源读取。缓存按 runtime 隔离，最多 32 个条目；session 范围资源按 session id，技能按工作区，内核资源按 transportEpoch 分开。模型配置缓存独立于内核连接，在本机写入后强制读取已脱敏快照。

没有轮询与自动重试。首次读取展示 loading；刷新保留已有数据；失败保留旧数据并暴露 error，下一次激活/手动刷新可重试。强制刷新或失效提升请求代际，迟到响应不覆盖新结果。非活跃 MCP 分区收到清单变化也标记失效，下次激活重新读取。MCP 更新不再连带重取插件/市场/技能。

分区的“重新读取”刷新该区资源；模型分区包含供应商与认证读回，技能包含技能、bundle、hooks。MCP/插件成功写入复用现有 onRefresh 失效链；provider 写入后重新读本机配置；应用认证在接受凭据后读回认证方式。缓存不存表单草稿、API Key 或完整配置，只存既有读接口返回的快照。

## 退出与表单

SettingsExitGuard 汇总各表单 dirty/busy，不保存输入值。Provider 比较当前草稿与打开时基线；认证检查未提交凭据；MCP 检查定义与 Setup 选择；插件检查来源及待确认仓库操作。

分区切换、返回工作区和模型编辑器关闭走同一退出入口。有修改时展示“继续编辑 / 放弃修改并离开”，取消保留表单、确认才执行目标动作；保存进行中阻止离开并提示等待。不将失败保存当作清空表单。模型 native CAS、审批/运行保护与重启流程保持原实现；MCP/插件的连接代际和 A/B/A 防护保留。

语言、主题和字号为立即生效的窗口偏好，不参加 dirty 确认。密钥仍只在表单内存及既有 native/内核保存路径中；退出注册表、缓存、窗口偏好与交付证据不记录输入值。

## 剩余边界

退出保护覆盖设置内部导航与模型编辑器关闭，不提供窗口强制退出、renderer reload 或操作系统终止时的草稿恢复。30 秒缓存不监听外部 CLI 文件写入；本机模型写入依赖既有 CAS 检测外部变化，手动刷新可读回。内核请求没有真实取消，迟到响应通过作用域/代际与卸载隔离。

Bundle 单项内容详情仍用原有选择请求与 token 防护，未纳入清单缓存；应用认证和 native provider 写入仍经原 Runtime 受限路径，不宣称设置全部协议已经搬入 SettingsClient。后续作为设置命令接口整理，不重新分散到页面。

下一个模块为文件工作区资源能力与生命周期：统一可预览类型、宿主打开行为、文件变更失效及资源恢复；保持内核独立。
