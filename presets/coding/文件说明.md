## 默认源码打包

```sh
python3 -B /home/none/nofy-build/presets/coding/build.py --output /absolute/coding-source.tar.gz
```

输出为普通tar.gz，根目录coding/。清单中的源码、声明、模块、Prompt、Schema、测试与依赖说明原样交付；本机Python/GCC、虚拟环境和缓存不打入包。不需要settings、模型连接、依赖锁或已安装业务依赖，不检查Python源码语法，不执行模块。仅检查文件齐全、模板引用、路径安全与归档正确，不覆盖现有输出。新增项目文件时把它加入source-files.json；不要把密钥、私有配置或安装目录列入源码清单。

外部依赖由用户自行安装。解压后的源码包不是/api/v1/import可直接接收的原生部署；现有执行后端的环境声明与权限边界不在打包阶段被绕过。默认源码交付不要求自动重建环境，详见docs/architecture/dependency-reconstruction-contract.md。

## 可选原生部署与装载

准备非凭据settings JSON，显式提供canonical绝对workspace、原生connection配置及该连接models内的model；profile只能显式选chat_completions、responses或messages。HTTPS为默认要求，HTTP必须allow_insecure_http=true；header_credentials只保存引用，凭据由内核部署环境独立注入。不得把API key写进headers、query、模板或生成部署。256k等窗口声明不自动转换为已验证容量或端点用量保证。

常规本地部署只提供`--settings`，其中environment按resource.process_local契约声明已安装程序、prefix_args、env及paths；不发现宿主PATH，不安装依赖，不要求版本/文件摘要。目录默认仅可读，execute=true才可执行；程序保留原调用位置，正常venv可使用其site-packages。启用命令时可另给command_environment，否则复用environment。实际导入/发布/新任务检查声明的路径是否可用，失败由用户处理；纯打包/validate不要求目标依赖已经安装。环境不能覆盖NOFY_DIRECTORY_绑定，也不能暴露内核私有根。

选择已有锁定环境时才同时给`--settings`和`--dependency-lock`，不能与environment/command_environment混用。锁格式为`nofy.dependencies/v1`，必填`runtimes.files`，内容仅有原生ImageManifest及AcquireImage来源锁；不含blobs或安装目录字节。目标环境独立配置信任/凭据，锁本身不授予下载权限；这不是默认源码交付门槛。

Python是这些外部模块的实现选择，不是框架的强制依赖。源码包与原生部署均不携带Python、GCC或库，本地环境不生成依赖映像。锁定模式的命令默认复用files依赖，也可在锁中提供`runtimes.command`；相同manifest只引用一个来源，矛盾来源拒绝。两种环境不是pip/uv/npm安装器；本项目不开发强制语言依赖安装适配器，不从宿主未声明位置隐式补齐。

terminal_enabled默认true，此时settings必须显式提供process_tree对象，其cgroup_root及limits沿用resource.process_tree_limits契约；真实委托须由宿主环境预先提供，打包器不配置系统服务。只需文件能力时显式terminal_enabled=false，不提供process_tree或command依赖锁：产物不含命令、可执行目录及树资源，审批与工具下限也不残留run_command。模板的$when仅控制列表项，关闭分支不读取源码，不把参数/$json内容当指令。

```sh
python3 -B /home/none/nofy-build/presets/coding/build.py --settings /absolute/settings.json --output /absolute/coding-deployment.json
python3 -B -m unittest discover -s /home/none/nofy-build/presets/coding/tests -p 'test_*.py'
```

输出是文件/API/后续控制台共用的原生部署。打包及POST /api/v1/validate均不下载/安装依赖；授权POST /api/v1/import在本地模式检查已声明路径，在锁定模式按来源取得并验签，随后/api/v1/apply激活。查询发布的programs接口取得chat输入契约，用稳定会话或运行API启动。读取、列举、搜索无需写审批；创建目录、写入、编辑及命令经过原持久审批流程，批准必须匹配完整请求。只读review不获得命令工具。用户管理的依赖变化不会自动生成generation，回滚声明不等于回滚外部安装；依赖暂缺不阻断历史记录和已成功效果恢复。不能把打包成功当成模型可用性或端到端完成。

run_command接受明确argv、项目相对cwd、文本stdin、timeout_ms和两流合计max_output_bytes；不插入隐式shell，不提供PTY/后台会话或网络。ok=false的error含code/message/effect；启动后的失败带实际结果且effect=unknown，可能已经修改项目，须先对账。成功也须检查退出码/信号、截断及有损UTF-8标志；observed字节只表示已观察，不保证是全部输出。完整边界见docs/architecture/command-module-contract.md，宿主编译C探针不能冒充Agent内GCC验收。

修改外部能力后重新打包，改变的模块和传递依赖取得内容版本，其他目录/预算等引用稳定。发布/应用不需Rust重编译或内核重启；进行中的运行继续原授权，实际运行中转换另走显式迁移契约。源目录是受信任管理员输入，不是任意不可信上传的执行入口。

这些文件通过Runtime的`resource.artifact`作为唯一代码制品装载，协议配置用`source.kind=artifact`和有序entries选择源码，并在同一制品中选择参数Schema；模型只引用protocol/connection资源。发布文档包含原始文件内容、版本与摘要，不由内核Rust按厂商静态注册源码。修改后须经相同管理入口发布/应用；此阶段的新运行装载证据不等于运行中完整热更新。

作用域以resource.scope_program声明artifact依赖、cwd、parameters和limits；tool.skills_scoped用scope字符串指定Resource依赖槽。grant工具名、路径参数及argv前缀来自参数，不提供Read/Bash旧DSL或包装器隐含授权。新旧发布及generation回滚通过相同import/apply入口；待审批运行继续绑定原制品，不自动采用新授权。

接纳按实际请求计算调用上限，普通请求一次，结构化修复至多六次；显式后续请求的已成功用量累加。没有用量的完成回复拒绝成功，不把未知成本记作零；Messages计入缓存读写输入token。拒绝不伪装修复，长度策略明确，最终答案和真实工具混批不得派发，所有无效批次工具结果均闭合后才修复。默认Host的六个模型协议求值阶段已在受限helper内执行，网络/凭据/预算仍归Rust驱动；其进程内存、故障与默认CPU轮换证据见docs/verification/model-program-isolation.md。管理制品仍要求可信授权，该模型边界不等于其他脚本引擎或整个扩展系统已全部隔离。

协议依据：工具流按调用项和参数片段组装，[OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)；原生reasoning项及加密内容保留回放，[OpenAI Reasoning](https://developers.openai.com/api/docs/guides/reasoning)；Messages的内容块/签名与累计用量按[Claude Streaming](https://platform.claude.com/docs/en/build-with-claude/streaming)处理。具体模型的可选参数仍须由显式连接/设置选择，不做模型名称猜测或自动登录恢复。
